### 数据结构基本概念

数据结构主要研究如何组织各种数据在计算机中的存储、传递和转换。广义上数据结构范围很广，本课程限定为内存中的数据组织。数据是信息的载体，是描述客观事物的数、字符以及所有能输入计算机并被程序识别和处理的符号集合。数据可分为数值型数据和非数值型数据；后者如姓名、图像、多媒体等，传统上不易直接比较大小，而现代 AI 在多媒体数据处理上取得了很大进展。

数据元素是数据的基本单位，在程序中常作为一个整体处理；一个数据元素可由若干数据项组成，数据项是具有独立含义的最小标识单位。数据元素又称元素、结点或记录。数据结构可抽象表示为二元组：

$$DS=(D,R)$$

其中 $D$ 是数据集合或数据对象，$R$ 是 $D$ 中数据元素之间关系的有限集合。数据结构技术就是根据不同的数据集合及元素关系，研究如何表示、存储和操作这些数据，操作包括查找、插入、删除、修改、排序等。

典型例子包括：学生选课表可看作二维数组；学生与课程通过选课关系连接，形成网状关系；UNIX 文件系统目录结构是树形结构。通过这些例子可以把表格、关系、层次等不同组织方式统一到数据结构视角下。

#### 逻辑结构

数据的逻辑结构从逻辑关系上描述数据，与数据在计算机中的存储位置无关，可以看作从具体问题抽象出来的数据模型。常见分类是：

- **线性结构**：如线性表。
- **非线性结构**：如树、图或网络。
- 部分教材还会增加集合结构，但内容通常较少。

逻辑结构关注元素之间是否存在前后关系、层次关系或网状关系，而不关注它们在内存中的具体地址。

#### 存储结构

存储结构是逻辑结构用计算机语言实现的表示，因此依赖具体语言及其提供的能力。常见存储表示包括：

- **顺序存储**：逻辑相邻则物理相邻，如数组。
- **链接存储**：逻辑相邻未必物理相邻，如链表。
- **索引存储**：为数据建立索引，通过索引访问数据。
- **散列存储**：根据数据关键码用散列函数计算存储地址。

同一逻辑结构可以有多种存储实现，例如树既可用数组存储，也可用链表等方式存储；后续课程会介绍多种树的存储方法。数据结构的抽象层次可从逻辑结构、基本运算、存储结构和算法实现等层面理解；常见抽象数据类型包括线性聚集中的数组、记录、表、栈、队列、优先队列，非线性聚集中的树、堆、集合、图，以及词典、散列表、广义索引等。

### 算法与性能分析

算法是有穷的指令集，为解决某一特定任务规定一个运算序列。算法通常具有以下特性：输入可有 0 个或多个；输出至少有一个处理结果；确定性要求每步定义确切无歧义；有穷性要求执行有穷步后结束；有效性要求每条运算足够基本。

评价算法性能不能只看运行快慢。常见标准包括正确性、可使用性与用户友好性、可读性、效率、健壮性与容错性、简单性等。本课程重点关注效率，即时间代价和空间代价；其他性质会在软件工程等课程中进一步强调。空间不足时系统可能使用虚拟内存，用磁盘模拟内存，而外存访问速度比内存慢若干数量级，因此程序设计常希望全内存运行；若不能，则需要设计缓存替换或内外存交换策略。

#### 事后测试

最直接的方法是事后测试：在程序中插装时间函数，记录开始和结束时间，求差得到运行时间。例如顺序搜索中可在调用前后读取 `time()`。事后测试的优点是直观、接近真实运行情况；缺点是受计算机系统、编译器、可用存储空间、后台负载等影响，同一算法在不同环境或不同状态下结果可能差异很大。当被测算规模很小时，计时精度不足，例如 `time()` 精度为 0.001 秒时，较小规模顺序搜索的测试结果可能全为 0。重复测量多次取平均可缓解规模过小问题，但 CPU 缓存会使后几遍更快，导致新的偏差。

因此，事后测试虽然“土”，但在科研和工程中仍非常常用。做实验时应保证可重复性，并报告硬件配置（CPU、GPU 等）、软件环境（语言及版本）、内存大小、磁盘类型等关键信息。课堂上以 1000 万个整数排序为例说明算法差异：快速排序大约在秒级以内，经过优化的其他排序可能降到几百毫秒甚至 0.1 秒级，说明算法选择会带来数量级差异。

#### 事前估计与复杂度

事前估计通过分析算法本身来评价其复杂性，与具体运行环境和编译器无关，只与算法写法有关。主要包括空间复杂度 $S(n)$ 和时间复杂度 $T(n)$，用于确定问题规模 $n$ 与算法所需存储空间、程序步数或时间开销之间的关系。时空复杂性分析是算法分析最重要的基本功之一，其中时间复杂度讨论尤为常见。

时间复杂度的本质是评价程序执行了多少步或多少指令节拍。精确计算指令节拍通常繁琐且难以算准，因此采用“抓主放小”的方法：关注执行次数最多的核心操作，忽略低阶项和常数因子。若核心部分执行次数为 $n^2$，非核心部分为 $n$，当问题规模趋向无穷大时，用 $O(n^2)$ 度量其复杂度。评价排序算法时，常抓住比较次数这一主要操作，例如快速排序的比较次数为 $O(n\log n)$，元素移动次数等低阶或同阶项在复杂度分析中可被概括处理。

教材还引入“程序步”概念：语法上或语义上有意义的一段指令序列，执行时间与实例特性无关。例如声明语句的程序步数可视为 0，表达式的程序步数可视为 1。编译时间与编译程序有关，与实例性质无关；运行时间则与输入实例有关。课程在本节尚未完整展开时间复杂度计算方法，下节课将继续补充，并讲解第一个 Project 的具体要求。

### 一、机考题目讲评：OJ 规则与三道题

#### 1. OJ 基本规则与复杂度估计

OJ 中每道题都有时间限制与空间限制，常见时间限制为 1 秒，空间限制可能是 256 MB、512 MB 等。评测机每秒大约能完成 \(10^8\) 数量级的运算。若程序运算量远远超过这一数量级，就可能出现 **TLE（Time Limit Exceeded）**。例如对长度为 \(10^5\) 的数组做冒泡排序，时间复杂度为 \(O(n^2)\)，运算量约为 \(10^{10}\)，显然会超时。

反过来，可以根据数据范围猜测正解复杂度。例如若 \(n,m\le 10^5\)，则正解通常不可能是 \(O(n^2)\)，更可能是 \(O(n\log n)\)、\(O(n\log m)\) 等；若 \(n\le 5000\)，则 \(n^2\approx 2.5\times 10^7\)，在 \(10^8\) 以内，\(O(n^2)\) 很可能是可接受的。常见提交状态包括：

- **AC（Accepted）**：程序正确并通过。
- **WA（Wrong Answer）**：运行正常，但答案错误。
- **RE（Runtime Error）**：运行错误，例如数组越界、除以零等导致程序异常终止。
- **MLE（Memory Limit Exceeded）**：内存超限。
- **TLE（Time Limit Exceeded）**：超时。

课堂还说明，该 OJ 的比赛赛制不是“通过部分数据就给部分分”，而是只有通过全部数据才能得到该题分数。因此算法必须针对完整数据范围设计。

#### 2. A 题：括号算式

题目给定一个包含 `+`、`-`、`*`、`^`（乘方）和括号的算式，要求计算其结果。乘方为**右结合**，且优先级最高，例如 \(2^{3^4}=2^{(3^4)}\)。算式长度可达 \(3\times 10^5\)，运算结果按 32 位自然溢出处理。

基本思路是用两个栈：一个存操作数，一个存运算符。各运算符优先级可设为：

| 运算符 | 优先级 |
|---|---:|
| `(`、`)` | 0 |
| `+`、`-` | 1 |
| `*` | 2 |
| `^` | 3 |

若暂不考虑括号，读取到某个运算符时，如果栈顶运算符的优先级不低于当前运算符，则可以先计算栈顶运算。例如对 `1+2*3^4-5`，读到 `*` 时不能先算 `1+2`，因为 `*` 的优先级更高；读到 `^` 时，前面的 `*` 也不能立即算，因为还要先处理更高优先级的乘方。计算顺序为：先算 \(3^4\)，再算 \(2\times 3^4\)，最后处理加减。核心原则是：**低优先级运算符出现时，前面所有同优先级或更高优先级的运算都可以结算**。

加入括号后：

- 遇到左括号 `(`：括号优先级最低，因此前面可计算的运算都可以先计算，将结果与左括号压栈。
- 遇到右括号 `)`：从右括号向前结算到与之匹配的左括号，弹出左括号。
- 由于乘方右结合，遇到 `^` 时不能把前面的 `^` 弹出计算，而应继续压栈，等待后续更高层或括号边界触发结算。

一种课堂代码框架是：`priority['(']=priority[')']=0`，`priority['+']=priority['-']=1`，`priority['*']=2`，`priority['^']=3`。定义 `process(level)`：当运算符栈顶优先级大于等于 `level` 时不断弹栈并计算。读入数字时用连续字符构造整数；遇到 `(` 直接压栈；遇到 `)` 调用 `process(1)` 并弹出左括号；遇到 `+`、`-` 调用 `process(1)` 后压栈；遇到 `*` 调用 `process(2)` 后压栈；遇到 `^` 直接压栈。最后清空运算符栈。乘方用快速幂，并按无符号 32 位自然溢出。

#### 3. B 题：最大伤害值

题目给定两个数组 \(a,b\)，矩阵定义为
\[
c_{ij}=a_i+b_j.
\]
要求找到一个最大的 \(D\)，使得矩阵 \(c\) 中大于 \(D\) 的数的数量满足题设阈值 \(K\)。该问题具有单调性：若 \(D\) 增大，则“大于 \(D\) 的数”的数量不会增加。因此可以二分答案。

二分时，每次取当前答案区间中点 \(mid\)，统计矩阵中有多少个数大于 \(mid\)。若数量满足条件，说明 \(mid\) 还可以增大；否则说明 \(mid\) 过大，需要减小。课堂代码中的判定写作 `num >= K`，若题面严格表述为“大于 \(K\)”，实现时应把判定改为 `num > K`，核心是利用计数的单调性。

关键问题是：如何在可接受时间内统计矩阵中大于 \(mid\) 的元素个数。矩阵大小为 \(10^5\times 10^5\)，元素数达 \(10^{10}\)，不能枚举。利用 \(c_{ij}=a_i+b_j\) 的特殊结构，可以先对 \(a,b\) 排序，使每一行 \(a_i+b_j\) 关于 \(j\) 单调递增。对固定的 \(a_i\)，需要统计满足
\[
a_i+b_j>mid
\]
的 \(j\) 的数量，即
\[
b_j>mid-a_i.
\]
在有序数组 \(b\) 上用 `upper_bound` 找到第一个大于 \(mid-a_i\) 的位置，后面的元素个数即为该行贡献。累加所有 \(a_i\) 的贡献即可得到矩阵中大于 \(mid\) 的元素总数。

因此算法为：排序 \(a,b\)；在外层对答案值域二分，内层对每个 \(a_i\) 在 \(b\) 上二分。单次 check 的复杂度约为 \(O(n\log m)\)，总复杂度再乘答案二分的次数。课堂代码使用 `upper_bound(b+1,b+m+1,mid-a[i])` 统计每一行的贡献。

#### 4. C 题：彩砖大师

题目有连续 \(n\) 个位置，其中初始有些位置已经铺砖。当在第 \(i\) 个位置铺砖时，若其左边连续已铺砖长度为 \(l\)，右边连续已铺砖长度为 \(r\)，则本次得分为
\[
l+r+1.
\]
要求把全部位置铺满后得分最大。

直接考虑“按什么顺序铺”较困难，可以倒过来考虑：一块空地中**最后被铺上的砖**应在哪里。若最后一块砖在边上，则它把长度为 \(n\) 的空地切成一块长度 \(n-1\) 的空地；若最后一块砖在中间位置 \(i\)，则会把空地切成两块。通过交换论证可知：对于一块连续空地，最优方案一定是从某一端开始，一直连续铺到另一端，而不会在中间零散铺。直观上，若某种操作序列在中间先铺，则后续两侧元素无法获得对方连续砖块带来的得分增益；把操作平移到边缘不会更差。

因此可以利用区间 DP。记 \(dp[l][r]\) 表示把区间 \([l,r]\) 全部铺满后的最大得分。若 \(l,r\) 本身为空地，则最后一块可能是 \(l\) 或 \(r\)；若 \(l\) 或 \(r\) 初始已有砖，则最后一块只能落在区间内最左空地或最右空地。实现时预处理：

- `L[i]`：位置 \(i\) 及其左侧最近的空地；
- `R[i]`：位置 \(i\) 及其右侧最近的空地。

对于区间 \([l,r]\)，最后一次铺砖若选在 `L[r]`，贡献为区间长度 \(r-l+1\)，再加上左右子区间的 DP 值；若选在 `R[l]`，同理。转移可写为
\[
dp[l][r]=(r-l+1)+\max\{dp[l][p-1]+dp[p+1][r]\},
\]
其中 \(p\) 取 `L[r]` 或 `R[l]` 这类可能的最后位置。初始时，若 \(s[i]\) 为空地，\(dp[i][i]=1\)；若本来有砖，\(dp[i][i]=0\)。最终答案为 \(dp[1][n]\)。该 DP 按区间长度从小到大计算，时间复杂度为 \(O(n^2)\)。

### 二、课程项目 PJ：内存索引

#### 1. 索引的基本概念

索引是为快速查找而建立的数据结构。给定数据集合
\[
D=\{\langle k_1,v_1\rangle,\langle k_2,v_2\rangle,\dots,\langle k_n,v_n\rangle\},
\]
其中 \(k\) 为键，\(v\) 为值。索引通常需要支持：

- **单点查找**：给定 \(k\)，若存在则返回对应 \(v\)，否则返回空值。
- **区间查找**：给定 \([L,R]\)，返回所有键在区间内的键值对。
- **插入**：把新的键值对加入集合。
- **删除**：删除指定键值对。
- **更新**：若键存在，则修改其值。
- **批量加载**：对初始数据集合建立索引。

不同工作负载与键值类型适合不同结构：只读负载可用有序数组加二分；数值型可用树状数组、线段树、平衡树；字符串可用 Trie；多维数据可用 k-d 树、R 树；不要求区间查找时可用哈希。设计目标是在内存占用尽量小的前提下，使查找、插入、删除尽量快。

#### 2. 三个 Lab 的内容

- **Lab1**：键值为 64 位无符号整数 `uint64_t`，支持单点查找、插入、删除，不支持区间查找；占总分约 10%。该 Lab 主要用于熟悉环境搭建、性能测试与常数优化，通常哈希索引是较自然的选择。
- **Lab2**：数值型键值，除单点查找外还支持区间查找，以及插入、删除；占总分约 30%。为了测试区间查找能力，单点查找改为 `lower_bound` 语义，即查找大于等于给定键的最小键。
- **Lab3**：字符串键值，支持单点查找、区间查找、插入、删除；占总分约 30%。字符串比较成本更高，Trie、ART 等结构更常见。
- **报告与汇报**：说明三个索引的设计、实现方法、实验结果与优化思路，约占总分 30%。

#### 3. 数据集、测试与评分

Lab1 共有 5 个数据集，每个数据集分数相同，各占总分约 2%。每个数据集约有 \(2\times 10^8\) 个键值，键值唯一，以二进制文件读入，约 16 亿字节，约 1.5 GB。每个数据集包含 5 种工作负载，各占该数据集分数的五分之一：

### 三、Lab1：哈希索引与 SwissTable

#### 1. 拉链法与开放地址法

哈希表把键值通过哈希函数映射到数组位置。不同键可能映射到同一位置，需要冲突解决。常见方法有两类：

- **拉链法**：每个桶维护一个链表，冲突元素挂在链表中。`std::unordered_map` 通常采用拉链法。若链表过长，一些实现会用红黑树替换长链，例如 Java 的 `HashMap`。
- **开放地址法**：冲突时按某种探测序列在数组中寻找下一个空槽。线性探测法每次向后看一个槽，直到找到目标或空槽。

拉链法的问题在于链表节点地址不连续，对现代 CPU 的缓存不友好。每次沿着链表访问下一个节点，都可能需要从内存重新读取数据，导致缓存未命中。开放地址法把元素放在连续数组中，利用空间局部性：CPU 读取一个缓存行通常为 64 字节，访问相邻槽位时大概率已在缓存中，速度明显更快。

#### 2. SwissTable 的结构

SwissTable 是 `absl::flat_hash_map` 等高性能哈希表采用的思路。与普通哈希表每个桶只放一个元素不同，SwissTable 的每个桶包含 16 个槽位，并额外维护一个 16 字节的控制字节数组，每个槽对应一个控制字节。控制字节标记该槽是空、满还是已删除，并可存储键哈希值的一部分，用于快速过滤。

对任意键 \(k\)，计算 64 位哈希值 \(H_1(k)\)。高位用于确定起始桶，低位或截断位作为短哈希 \(H_2(H_1(k))\)，存入控制字节。查找时，先计算起始桶，读取该桶的 16 个控制字节，利用一次比较或 SIMD 指令快速判断哪些槽的控制字节与待查键的短哈希匹配。只有控制字节匹配的槽才需要进一步比较完整键值；控制字节不匹配则一定不匹配，从而减少昂贵的键比较。

查找过程为：

1. 从桶 \(H_1(k)\bmod n\) 开始；
2. 读取该桶控制字节数组，查找可能的短哈希匹配；
3. 若控制字节匹配，则比较完整键值；相等则返回；
4. 若当前桶满且未找到，则继续查找下一个桶；
5. 若当前桶未满且没有匹配元素，则说明哈希表中不存在该键。

插入时，从起始桶开始，读取控制字节寻找空槽；若当前桶有空槽则插入；若没有则继续下一个桶。删除时不能直接把槽设为空，否则会破坏线性探测的查找链。SwissTable 会根据下一个位置是否为空来决定把控制字节设为 `Empty` 还是 `Deleted`：若下一个位置为空，可设为 `Empty`；否则设为 `Deleted`，表示这里曾经有元素但已被删除，查找时仍需继续向后探测。

SwissTable 每个桶装 16 个元素，还能降低每个桶内元素数量的方差，减少最坏情况下的查找延迟。与 `std::unordered_map` 相比，它的内存布局更连续、控制字节可批量比较、缓存局部性更好，因此性能提升显著。

#### 3. 缓存局部性与 SIMD

现代 CPU 通常有多级高速缓存：每个核有寄存器、独立的 L1 指令缓存与数据缓存、L2 缓存；多个核共享 L3 缓存。CPU 读数据时依次查 L1、L2、L3，再到内存。缓存行一般为 64 字节，因此一次从内存读入至少 64 字节，并可能预取后续数据。读取相邻地址或刚刚读过的地址时，大概率命中缓存。这就是空间局部性与时间局部性。

哈希表设计要尽量让数据连续存放，减少指针跳转和随机访问。SwissTable 的桶结构、控制字节数组和批量比较都是缓存友好的体现。除此之外，现代 CPU 支持 SIMD（Single Instruction Multiple Data）指令集，例如 AVX512、AVX2、SSE、ARM 的 NEON。一条 SIMD 指令可以同时比较多个字节或多个整数，例如一次比较 16 个控制字节，快速找出可能匹配的槽。

使用 SIMD 可以在编译时加入 `-mavx2` 等选项，让编译器对某些循环自动向量化；也可以使用 intrinsics，例如 `_mm_loadu_si128`、`_mm_cmpeq_epi8`、`_mm_movemask_epi8`。但课堂强调：**索引的整体设计和内存布局才是性能的关键**，常数优化应在索引结构完成之后再做，不必一开始就陷入 SIMD 细节。Linux 下可用 `grep -m1 flags /proc/cpuinfo` 查看 CPU 支持的指令集。

#### 4. 其他哈希优化

线性探测法在插入元素增多后，元素可能离其本应位置越来越远。Robin Hood 哈希在插入时计算当前位置与哈希位置的偏移量
\[
D(k)=\text{实际位置}-\text{hash}(k).
\]
若待插入键的偏移量 \(D(k)\) 大于当前位置已有键的偏移量 \(D(k')\)，则“劫富济贫”，把待插入键与已有键交换，再继续向后探测被替换的键，直到找到空槽。这样可以减小最大探测长度，降低尾部延迟。

另外，静态负载可使用完美哈希函数避免冲突；学习型哈希算法也可用于减少冲突。课堂鼓励学生自行探索其他索引结构。

### 四、算法复杂性分析

#### 1. 程序步方法

评估运行时间的一种朴素方法是统计“程序步”：在程序中插入全局计数变量 `count`，对每条语句按执行次数累加，最后得到一个关于问题规模 \(n\) 的函数。例如累加求和函数：

```cpp
float sum(float a[], int n) {
    float s = 0.0;
    for (int i = 0; i < n; i++)
        s += a[i];
    return s;
}
```

按课堂计数方式，可得到程序步数约
\[
T(n)=3n+4.
\]
其中初始化、循环判断、循环体、最后一次判断和 `return` 分别贡献不同步数。若调用 `sum` 的语句本身也算一步，则赋值语句 `x=sum(a,n)` 的总程序步数可能为 \(3n+5\)。

但程序步方法有明显局限：

- 精确统计程序步非常繁琐；
- “程序步”本身不是精确概念，不同语句的实际代价差异很大；
- 函数调用、库函数、除法、内存访问等操作的代价难以用统一步数衡量；
- `x=a` 与 `x=a+b*(c-d)-e/f` 可能被粗略地都算作少量程序步，但实际 CPU 代价不同。

因此程序步方法主要用于建立“抓主要矛盾”的思想，而不是精确比较程序。真正分析时只关注循环、递归中的关键操作。

#### 2. 大 O 表示法与渐进复杂度

当问题规模 \(n\) 趋于无穷大时，忽略低阶项和常数系数，只保留增长最快的项。例如
\[
T(n)=2n^3+3n^2+2n+1
\]
的数量级为
\[
T(n)=O(n^3).
\]
这里 \(n^3\) 是最高阶项，系数 2 与低阶项在 \(n\to\infty\) 时都可忽略。

大 O 的正式定义为：若存在正常数 \(c\) 与 \(n_0\)，使得对所有 \(n\ge n_0\) 都有
\[
T(n)\le c f(n),
\]
则称
\[
T(n)=O(f(n)).
\]
大 O 描述的是最坏情况下的渐进上界。本课程中，除非特别说明，一般讨论最坏情况复杂度；平均情况与最好情况在实际中重要性相对较低，但在某些问题中也会讨论。

渐进复杂度只在 \(n\) 很大时有效。问题规模较小时，低阶项与常数系数可能起决定作用。例如快速排序平均复杂度为 \(O(n\log n)\)，但小规模数据时插入排序的常数更小，实际可能更快；STL 的排序实现会在小区间使用插入排序。相同渐进阶的算法还需要比较常数，例如快速排序在同类 \(O(n\log n)\) 算法中常数较小，因此平均性能好。

#### 3. 复杂度计算规则与常见阶

常见复杂度从低到高大致为
\[
c<\log_2 n<n<n\log n<n^2<n^3<2^n<3^n<n!.
\]
对数底数不影响渐进阶，因此 \(O(\log n)\)、\(O(\ln n)\)、\(O(\log_2 n)\) 可视为同一类。\(O(2^n)\)、\(O(3^n)\)、\(O(n!)\) 等指数级或阶乘级算法在 \(n\) 稍大时计算代价急剧增大，通常视为非多项式时间算法。

复杂度计算常用规则：

- **单个循环**：若循环执行 \(n\) 次，循环体为常数时间，则复杂度为 \(O(n)\)。
- **并列程序段**：使用加法规则，
\[
T(n,m)=T_1(n)+T_2(m)=O(\max(f(n),g(m))).
\]
若两个变量独立且无法比较，则不能随便去掉某一项；若已知相关性，例如图的边数 \(E\le V^2\)，则可在 \(O(V^2+E)\) 中把 \(E\) 吸收到 \(V^2\) 中。
- **嵌套循环**：使用乘法规则，
\[
T(n,m)=T_1(n)\cdot T_2(m).
\]
例如外层 \(m\) 次、内层 \(n\) 次，复杂度为 \(O(mn)\)；三层循环可能得到 \(O(n^3)\)。

例如：

```cpp
x = 0; y = 0;
for (int k = 0; k < n; k++) x++;
for (int i = 0; i < n; i++)
    for (int j = 0; j < n; j++) y++;
```

第一段为 \(O(n)\)，第二段为 \(O(n^2)\)，并列取最大值，总复杂度为 \(O(n^2)\)。

#### 4. 空间复杂度

空间复杂度分为固定部分与可变部分。

固定部分包括：

- 程序指令代码本身占用的空间；
- 初始数据结构占用的空间；
- 常数、简单变量、定长数组元素、结构体成员、对象数据成员等。

可变部分包括：

- 程序运行过程中临时申请的空间；
- 与实例特性有关的成分变量；
- 引用变量；
- 递归调用栈；
- `new`、`delete` 动态申请的空间。

空间复杂度分析主要关注可变部分，尤其是递归栈与动态申请。实际工程中还要注意：若程序使用的内存超过物理内存，操作系统会启用虚拟内存，用磁盘模拟内存，程序性能会急剧下降。因此需要定量估算内存，包括数组、对象、递归栈等，并留出系统与其他程序占用的余量。

#### 5. 事前估计与事后测试

复杂度分析属于**事前估计**：在程序运行前，从最坏情况或已知数据分布出发，估计程序代价。它能全面分析算法随问题规模增长的趋势，但难以给出具体运行时间。

**事后测试**则实际运行程序，测量特定数据与特定环境下的时间和空间。它能获得真实数据，但结果依赖具体数据、机器与实现，需要多次测试并精心设计测试数据。两者在实际中都有价值，不能因为学了渐进分析就完全放弃实验测试。

### 五、线性表、数组与特殊矩阵压缩

#### 1. 线性表的定义与 ADT

线性表是最基础的数据结构之一。线性结构中的元素按顺序排列，除第一个元素外，每个元素最多有一个直接前驱；除最后一个元素外，每个元素最多有一个直接后继。线性表可以为空。实际中一维表格是线性表；二维表可以看作每个元素又嵌套一个线性表，例如每个职工记录包含若干字段。

抽象数据类型（ADT）把数据与操作封装在一起。线性表 ADT 通常包括：求长度、遍历、访问第 \(i\) 个元素、赋值、插入、删除、查找等。实现方式主要有：

- **顺序表**：用数组存储，支持随机访问；
- **链表**：用指针连接节点，插入删除灵活，但随机访问需要沿链查找。

#### 2. 数组的地址计算

一维数组顺序存储的最大优点是支持随机存取，访问和修改都可以 \(O(1)\) 完成。设数组首地址为 `base`，每个元素占 \(L\) 字节，下标从 0 开始，则第 \(i\) 个元素的地址为
\[
\operatorname{loc}(a_i)=\text{base}+iL.
\]
在 C/C++ 中，数组名可视为地址常量，`A+i` 会自动按元素类型大小缩放，不需要手动乘 `sizeof`。例如 `A[i]` 的地址等价于 `A+i` 的地址。

二维数组在逻辑上是二维的，但内存地址空间是一维线性的。C/C++ 通常采用行优先存储：先存第 0 行，再存第 1 行，以此类推。设二维数组有 \(N\) 列，每个元素占 \(L\) 字节，则
\[
\operatorname{loc}(A[i][j])=\text{base}+(iN+j)L.
\]
三维、四维乃至 \(N\) 维数组都可类似展开，按各维大小累乘后加上偏移。课堂强调：实际内存地址是一维的，多维只是逻辑概念。

#### 3. 对称矩阵、三角矩阵与带状矩阵

特殊矩阵中非零元素或零元素分布有规律，可以通过压缩存储减少空间。典型例子是对称矩阵：若 \(A[i][j]=A[j][i]\)，则只需存储一半元素。例如微信好友关系矩阵是对称的，若两人是好友则值为 1，否则为 0，上下三角重复。

以下三角矩阵为例，采用 0 基下标，只存储 \(i\ge j\) 的部分，并按行优先放入一维数组 \(B\)。第 0 行存 1 个元素，第 1 行存 2 个元素，……，第 \(i\) 行存 \(i+1\) 个元素。元素 \(A[i][j]\) 前面的元素个数为
\[
1+2+\cdots+i=\frac{i(i+1)}2,
\]
其在一维数组中的下标为
\[
k=\frac{i(i+1)}2+j.
\]
上三角矩阵类似，若只存储 \(i\le j\) 的部分，则
\[
k=\frac{j(j+1)}2+i.
\]
对称矩阵可只存下三角，访问上三角时交换 \(i,j\) 后套用下三角公式。

带状矩阵是另一种常见压缩对象。例如每行最多有 3 个非零元素的带状矩阵，非零元素位于主对角线及其左右相邻位置。采用 0 基下标，且 \(j\in\{i-1,i,i+1\}\) 时，前 \(i\) 行贡献的元素个数为：第 0 行有 2 个元素，第 1 至第 \(i-1\) 行各有 3 个元素，因此前面共有
\[
2+3(i-1)=3i-1
\]
个元素。当前行内，元素 \(j\) 相对于该行第一个元素 \(i-1\) 的偏移为
\[
j-(i-1).
\]
所以
\[
k=(3i-1)+j-i+1=2i+j.
\]
这就是带状矩阵压缩到一维数组后的下标映射。边界行元素较少，但公式在上述范围内成立。

课堂还介绍了一种快速推导线性下标公式的方法：若下标关系是线性的，可假设
\[
k=aI+bJ+c,
\]
代入几个简单位置（如 \((0,0)\)、\((0,1)\)、\((1,0)\)）解出 \(a,b,c\) 并验证边界。对带状矩阵可得 \(k=2i+j\)。这种方法对线性关系很高效，适合编写循环和边界条件时快速自检。

#### 4. 二维动态数组与缓存友好的压缩实现

课堂用二维动态数组演示了二级指针、指针数组、数组指针与二维数组的关系。普通二维动态数组可写成：

```cpp
int **a = new int*[n];
for (int i = 0; i < n; i++)
    a[i] = new int[m];
```

对下三角矩阵，可以只给第 \(i\) 行分配 \(i+1\) 个元素：

```cpp
int **a = new int*[n];
for (int i = 0; i < n; i++)
    a[i] = new int[i + 1];
```

访问时保证 \(j\le i\)，即可用 `a[i][j]` 形式访问，逻辑上仍像二维数组，但不再存储上三角的空白区域。

对上三角矩阵，若希望仍然写 `a[i][j]` 且只存 \(j\ge i\) 的部分，可以为第 \(i\) 行分配长度 \(n-i\) 的连续空间，但把指针向前偏移 \(i\) 个位置，使得 `a[i][j]` 实际访问到该行第 \(j-i\) 个元素。课堂展示了这一“指针回退”的技巧。需要注意，这种写法依赖指针运算，实际工程中应确保符合语言规范并做好封装；其教学价值在于说明逻辑下标与物理存储可以分离。

更进一步，为了缓存友好，可以把所有有效元素放入一个连续一维数组，通过下标映射函数访问，例如下三角用
\[
k=\frac{i(i+1)}2+j,
\]
上三角用
\[
k=\frac{j(j+1)}2+i,
\]
带状矩阵用
\[
k=2i+j.
\]
然后封装 `get(i,j)`、`set(i,j)` 接口，在接口中检查 \(i,j\) 的合法关系。这样既保持 `A[i][j]` 式的可读性，又避免大量离散 `new` 造成的缓存不友好。课堂指出，现代 CPU 的缓存命中率对实际性能影响越来越大，指针分散分配会导致缓存局部性差；连续存储、按行压缩、减少随机跳转，往往比单纯减少程序步数更重要。

#### 最大子段和

题目给定长度为 $n$ 的整数序列 $a_1,\dots,a_n$，要求找到一个子区间 $[l,r]$，使区间和尽可能大。数据范围 $n\le 10^5$，因此需要线性或 $O(n\log n)$ 做法。

核心是利用前缀和。定义
$$
S_0=0,\qquad S_i=\sum_{t=1}^{i}a_t .
$$
则区间 $[l,r]$ 的和为
$$
\sum_{t=l}^{r}a_t=S_r-S_{l-1}.
$$
以 $r$ 为右端点时，需要最大化 $S_r-S_{l-1}$，等价于最小化 $S_{l-1}$。因此预处理前缀最小值
$$
M_i=\min_{0\le j\le i}S_j.
$$
对每个右端点 $r$，若允许空区间，则以 $r$ 结尾的最大区间和为 $S_r-M_r$；若题目要求非空区间，则实现时应使用 $M_{r-1}$，或者在计算完当前 $r$ 后再把 $S_r$ 并入最小值。最终答案为所有右端点结果的最大值。

做法分为三步：预处理前缀和 $S_i$，复杂度 $O(n)$；预处理前缀最小值，复杂度 $O(n)$；枚举右端点 $r$，用 $O(1)$ 计算以 $r$ 结尾的最大区间和并取最大值，复杂度 $O(n)$。总复杂度 $O(n)$，空间复杂度 $O(n)$。

#### 看番

题目给定若干精彩片段 $[l_i,r_i]$，从第 $1$ 分钟开始观看。每次可以按快进键，使当前时间从 $i$ 跳到 $i+x$，但不能跳过任何精彩片段。问看完所有精彩片段最少需要多少时间。

关键观察：若从 $i$ 跳到 $i+x$，会跳过区间 $[i+1,i+x]$。如果这个区间内没有精彩片段，那么就可以安全快进；如果有精彩片段，就不能直接跳过。因此只需要考虑相邻精彩片段之间的空档。设某两个相邻片段之间的纯空档长度为 $g$，则最多可以快进
$$
\left\lfloor \frac{g}{x}\right\rfloor
$$
次，其余时间自然流逝。把所有可跳过的空档节省掉，即可得到最短观看时间。实现时需要先按时间处理片段，合并或正确处理重叠片段，并只对真正没有精彩片段的空档快进。

#### 2 进制高精度乘法

题目给定两个二进制整数，求乘积并以二进制输出。做法是模拟竖式乘法，本质上就是多项式乘法：一个二进制数的每一位是系数，指数对应该位权值。例如
$$
101_2=1\cdot 2^2+0\cdot 2^1+1\cdot 2^0.
$$
把两个二进制串倒序存入数组，使低位在前。设 $a_i,b_j\in\{0,1\}$，则乘积中第 $i+j$ 位的贡献为 $a_i b_j$。若采用 $0$ 下标，可写成
$$
ans[i+j]\mathrel{+}=a_i b_j.
$$
然后从低位向高位处理进位：
$$
ans[i+1]\mathrel{+}=\left\lfloor \frac{ans[i]}{2}\right\rfloor,\qquad
ans[i]\bmod 2.
$$
最后删除高位前导零并倒序输出。

课堂上展示的代码使用 $1$ 下标，因此出现 $i+j-1$ 这种写法。教师建议尽量改成 $0$ 下标：这样 $a_i$ 正好表示 $2^i$ 的系数，$b_j$ 表示 $2^j$ 的系数，$ans[i+j]$ 自然对应乘积位，能减少边界错误。总复杂度为 $O(nm)$，其中 $n,m$ 为两个二进制串长度。

#### 你的数太多了

题目给定一个大小为 $n$ 的有序可重数列，要求删除所有出现次数超过一次的数字，输出操作后的数列。课堂借此科普 C++ STL 中的 `map` 与 `unordered_map`。

`map` 存储键值对，键为数字，值为出现次数。遍历数组时执行 `mp[x]++`，再遍历 `map`，只保留出现次数为 $1$ 的数字。由于 `map` 默认按 key 升序排列，输出天然有序。`map` 插入和查询复杂度为 $O(\log n)$，总复杂度 $O(n\log n)$。

`unordered_map` 基于哈希，期望插入和查询复杂度为 $O(1)$，总复杂度期望 $O(n)$。但由于无序，不能直接依赖它输出有序结果。可在统计完次数后，再按原数组顺序遍历，输出 `mp[x]==1` 的元素。这样既保留原数列顺序，又获得线性期望复杂度。课堂代码即采用 `unordered_map` 计数，再按原数组筛选。

#### 姓名格式化

题目给定 $n$ 个英文姓名，每个姓名由姓和名两个字符串组成，要求将每个字符串格式化为首字母大写、其余字母小写。

由于姓和名的处理方式完全一样，优秀写法是抽象出统一的 `transform` 函数，分别对姓和名调用。函数内部先处理首字母：若为小写则转大写；再遍历其余字符：若为大写则转小写。主程序读入 `s1,s2`，调用两次 `transform` 后输出。这样代码复用性好，逻辑清晰，也不容易在姓和名上重复写错。

#### 最小乘积

题目给定 $a,b,x,y,n$，满足 $a\ge x$，$b\ge y$。最多进行 $n$ 次操作，每次选择：

- 令 $a\leftarrow a-1$，要求 $a\ge x$；
- 令 $b\leftarrow b-1$，要求 $b\ge y$。

求操作后 $ab$ 的最小值。

课件中“根据均值不等式，要使乘积最小应使 $a,b$ 尽可能接近”的说法是**写反了**。正确结论是：当 $a+b$ 固定时，由
$$
\frac{a+b}{2}\ge \sqrt{ab}
$$
可知乘积在 $a=b$ 时最大，在两端时最小。因此要使 $ab$ 尽可能小，应让 $a,b$ **尽可能远离**，即尽量把其中一个减到下限，而不是让它们接近。

实现时不妨先令 $a\le b$；若 $a>b$，则交换 $a,b$，同时交换 $x,y$。分两种情况：

1. 若 $a-x\ge n$，说明把 $a$ 减 $n$ 次仍不会低于下限，则全部操作用于减小 $a$，答案为
$$
(a-n)b.
$$
2. 若 $a-x<n$，先把 $a$ 减到 $x$，消耗 $a-x$ 次操作；剩余 $n-(a-x)$ 次用于减小 $b$，但 $b$ 不能低于 $y$，故答案为
$$
x\cdot \max\bigl(y,\;b-(n-(a-x))\bigr).
$$
答案可能较大，应使用 `long long`。

#### $1\cdot2\cdot3=6$

题目给定一个长度为 $n$ 的排列 $p_1,\dots,p_n$，统计合法四元组 $(a,b,c,d)$ 的数量。合法条件为：

- $1\le a<b<c<d\le n$；
- 四个数在排列中的出现位置递增；
- $a\cdot b\cdot c=d$。

课堂代码令 `p[x]=i`，即数组 `p` 存储“值 $x$ 在排列中出现的位置”。于是位置递增条件可写成
$$
p[a]<p[b]<p[c]<p[a\cdot b\cdot c].
$$
枚举 $a,b,c$ 作为值，并令 $d=a\cdot b\cdot c$。若 $d\le n$ 且上述位置不等式成立，则找到一个合法四元组。由于 $a<b<c<d$ 且 $d\le n$，有 $a\cdot b\cdot c\le n$，可据此大幅剪枝。

复杂度证明是本题重点。因为 $a^3\le a b c\le n$，所以
$$
a\le n^{1/3}.
$$
固定 $a$ 后，由 $a b^2\le a b c\le n$，得
$$
b\le \sqrt{\frac{n}{a}}.
$$
再固定 $a,b$，由 $a b c\le n$，得
$$
c\le \frac{n}{ab}.
$$
因此总枚举次数满足
$$
T\le \sum_{a=1}^{n^{1/3}}\sum_{b=a+1}^{\sqrt{n/a}}\frac{n}{ab}
=O(n\log^2 n).
$$
直观上，$a$ 的范围远小于 $n$，$b$ 的范围继续缩小，$c$ 的范围更小，因此虽然表面是三重循环，实际复杂度远低于 $O(n^3)$。内层对 $b$ 求和为调和级数 $O(\log n)$，外层对 $a$ 求和也是调和级数 $O(\log n)$，故总复杂度为 $O(n\log^2 n)$。

### 线性表的顺序表示

线性表是最简单也最常用的数据结构。教材通常先给出抽象数据类型定义，再讨论两种实现：顺序表和链表。顺序表把线性表中的元素相继存放在连续存储空间中，可用一维数组描述。特点是所有元素具有相同数据类型，逻辑相邻元素在物理上也相邻，因此支持 $O(1)$ 随机访问。

课堂展示了顺序表类 `SeqList` 的定义，包括构造函数、析构函数、求表长、查找、判断存在、插入、删除、找前驱后继、判空、判满、取第 $i$ 个元素等接口；私有成员包括存储数组、最大容量和当前最后位置。代码本身是常规面向对象写法，不需要逐行记忆。教师借此强调：类本质上是一种更大粒度的代码复用。循环是代码复用，函数是代码复用，对象是一组相关函数与数据的复用，更高层还有服务、框架等；AI 辅助编程也可视为另一种形式的代码复用。

顺序表的优点是存储利用率高、存取速度快，可通过下标直接定位；缺点是元素个数不能自由扩充（动态数组可缓解），在中间插入或删除元素会导致大量元素移动，最坏和平均复杂度为 $O(n)$，还可能造成空间浪费。

### 链表

链表用不连续的存储空间表示线性表。每个元素由结点构成，结点包含数据域 `data` 和指针域 `link`。结点之间可以连续，也可以不连续；结点的逻辑顺序与物理顺序可以不一致；表可以扩充。

使用链表的核心动机是解决顺序表中间插入删除时的大量元素移动问题。顺序表相邻元素地址间距为常数，因此可 $O(1)$ 随机访问；但插入删除需要移动元素，代价 $O(n)$。链表在已经定位到修改位置后，插入删除只需修改若干指针，代价 $O(1)$。

但教师特别提醒：**不能断章取义地夸大链表优势**。链表插入删除为 $O(1)$ 有前置条件——已经找到插入或删除位置。若需要从表头沿链查找第 $k$ 个位置，定位本身已经是 $O(n)$。在顺序表中，若同样已经知道下标，定位是 $O(1)$；若按值查找，两者都可能需要 $O(n)$。因此只有在“修改点已经确定”这一同等代价前提下，链表的 $O(1)$ 增删优势才成立。

链表优点是插入删除频繁、存储空间需求不定时较灵活；缺点是随机访问慢、缓存局部性差、调试困难。教师结合工程经验指出：在今天 CPU 多级缓存结构下，数组的连续存储具有更好的缓存命中率，时间复杂度估算在实际性能评价中会打折扣；而链表程序几乎无法用调试工具一次性观察全局结构，调试成本很高。因此当数组和链表效率接近时，他个人更倾向选择数组：代码更简明、更易调试、缓存更友好。不要被某些教材措辞误导为“链表更高级”。

#### 单链表与辅助表头

单链表结点由 `data` 和 `link` 构成，多个类可以表达单链表概念：链表结点类和链表类。定义方式有复合方式、嵌套方式、继承方式和结构方式；C++ 中常用复合方式，继承方式较牵强，不建议使用。

单链表插入分三种表面情况：表头插入、中间插入、表尾插入。表头插入需要修改 `first`：
```
NewNode->link = first;
first = NewNode;
```
中间插入，设在 `current` 后插入：
```
NewNode->link = current->link;
current->link = NewNode;
```
两条语句顺序不能反，否则会丢失原后继。表尾插入若用尾指针 `last`，写法与中间插入类似。

教师强调：**默认应加辅助表头结点（哨兵结点）**。辅助表头位于表最前端，本身不存数据，仅标志表头。很多教材说其目的是“统一空表与非空表操作”，这个说法不到位。更本质的作用是：不再需要修改表头指针 `first`，插入删除不再区分是否发生在表头，所有位置都可用同一套代码处理；同时函数传参时可把表头指针作为只读参数，封装更好，减少误改。教师认为几乎举不出“不加辅助表头会更好”的反例。带辅助表头后，空表就是头结点 `link` 为空；非空表也从辅助头之后开始。

有些教材把表尾单独列为第三种情况，这是糟糕的叙事。实际上表尾与中间插入写法一致，只需用 `current` 指针；只有表头是特殊位置。辅助表头消除了表头特殊性，因此代码归一。

建立单链表有前插法和后插法。前插法从空表开始，反复读入数据，生成新结点并插入链表前端，直到结束符；后插法设置尾指针 `last` 指向最后一个结点，每次把新结点插到表尾并更新 `last`。多项式的链表表示中，每个结点可存系数 `coef`、指数 `exp` 和后继指针，优点是项数可动态增长、插入删除方便、不移动元素。

#### 循环链表、双向链表与带尾指针链表

循环链表是单链表的变形：最后一个结点的 `link` 不为 `NULL`，而指向表前端；通常也加入表头结点。判断是否到达链尾时，不再判断 `current->link==NULL`，而是判断 `current->link==first`。循环链表的特点是：只要知道表中某一结点地址，就可以沿链搜索到所有其他结点。搜索时沿 `link` 一直走，直到回到起点或找到目标。

约瑟夫问题是循环链表的经典例子：$n$ 个人围成圆圈，从第 $1$ 个人开始报数，报到第 $m$ 个人出列，然后从下一个人继续报数，直到只剩一人。用循环链表模拟时，每次删除一个结点需要沿链走 $m$ 步，共删除 $n-1$ 个结点，因此时间复杂度为
$$
O(nm).
$$
若用数组并做删除标记，最朴素实现每轮要在数组中寻找第 $m$ 个未删除位置，上界可为 $O(n^2)$；课堂最后进一步讨论：若每轮剩余 $K$ 个活人，数 $m$ 个活人平均需跨过约 $mN/K$ 个物理位置，累加可得到更精细的 $O(mN\log n)$ 量级；当 $m$ 视为常数时即 $O(n\log n)$。这说明数组实现并非简单等同于循环链表，具体取决于是否优化“寻找下一个活人”的过程。

若插入删除只在链表两端发生，可用带尾指针的循环链表，便于实现双端队列。双向链表每个结点有 `lLink`、`data`、`rLink`，可向前驱和后继两个方向遍历；双向循环链表可高效支持两端操作，是双端队列的常见基础结构。

### 稀疏矩阵与快速转置

稀疏矩阵指非零元素远少于总元素、且分布无明显规律的矩阵。矩阵稠密度定义为非零元素数量与总元素数量之比，通常认为稠密度小于 $5\%$ 时可视为稀疏矩阵。稀疏矩阵不需要用完整二维数组存储，只存非零元素即可。常见格式包括 COO、CSR、CSC、BSR、DOK、LIL、DIA 等，课堂重点讲最简单的 COO 坐标格式。

COO 用三元组 `(row,col,data)` 存储每个非零元素，一般要求按行号为第一关键字、列号为第二关键字升序排列。排序的必要性在于查找：若三元组乱序，判断某个位置是否有值可能需要全表扫描；有序后可以二分定位行，再二分定位列，显著提高效率。

矩阵转置满足
$$
(A^T)_{i,j}=A_{j,i}.
$$
即把每个三元组的行号与列号交换，并且转置后仍要按行、列有序。朴素做法可以枚举原矩阵列号 $k$，每次扫描所有三元组，把列号为 $k$ 的元素转置后放入结果；若列数为 $m$、非零元素数为 $t$，复杂度为 $O(mt)$，较慢。另一种先转置再排序的方法为 $O(t\log t)$，在特定情况下也未必优。

快速转置利用前缀和思想。先统计转置后每一行有多少个非零元素，存入 `rowSize`；再对 `rowSize` 做前缀和，得到每一行在结果三元组表中的起始存放位置 `rowStart`：
```
rowStart[0]=0;
rowStart[i]=rowStart[i-1]+rowSize[i-1];
```
然后依次扫描原三元表，对元素 `(row,col,data)`，它在转置后应放在第 `col` 行，位置为 `rowStart[col]`；放入后执行 `rowStart[col]++`，使同一行下一个元素放到下一位置。这样只需线性扫描，且结果自然有序。设原矩阵列数为 $m$、非零元素数为 $t$，统计和前缀和需 $O(m)$，扫描插入需 $O(t)$，总复杂度
$$
O(t+m).
$$
课堂强调：前缀和不是小技巧，而是必须掌握的基本方法，后面计数排序等场景还会反复使用。

### 静态链表

静态链表用数组实现链表：逻辑上是链表，物理上是数组。每个结点包含 `data` 和 `link`，但 `link` 不是指针，而是下一个结点在数组中的下标。整个运算过程中数组大小固定，不能动态扩充。它适用于不支持指针的高级语言，或数据元素容量固定不变的场景，如操作系统文件分配表 FAT。

静态链表保留链表的灵活性：不改变元素物理位置，只通过重新链接改变逻辑顺序；同时具有数组的缓存局部性，访问范围固定。缺点是容量固定。初始化时通常维护一个头结点 `head` 和一个空闲链表指针 `avail`；分配空间时从 `avail` 取一个空闲下标，回收时把结点重新挂回空闲链表。

例如在数据 $30$ 后插入 $70$：先定位到 $30$ 所在结点，从 `avail` 分配一个空闲下标，填入 $70$；然后令 $70$ 的 `link` 指向原来 $30$ 的后继，再令 $30$ 的 `link` 指向 $70$；最后更新 `avail` 指向下一个空闲块。若涉及指针交叉引用，可用临时变量保存，避免断链。回收操作类似，把被删结点挂回空闲链表。FAT 文件系统就是静态链表的经典应用：磁盘簇数量固定，用表项记录空闲簇、保留簇、被占用簇的下一簇、坏簇、文件最后簇等状态。

### 块状链表

块状链表是数组和链表的混合结构：整体看成一个链表，每个链表结点中存放一个长度相等的小数组。设每个小数组长度为 $N$，总元素数为 $M$。$N$ 越小，块内插入删除越快；$N$ 越大，块内遍历越快。极端地，$N=1$ 退化为链表，$N=M$ 退化为数组。

在末尾插入时，先沿链找到最后一块，在其小数组尾部插入；若已满，则把该块分裂成大小为 $1$ 和 $N-1$ 的两块，再插入。在中间位置 $x$ 插入时，通过每个块记录的元素数量定位到对应小数组，在块内数组插入；若超过 $N$ 则分裂。删除时定位并删除元素；若该块元素少于 $\lfloor N/2\rfloor$，从后一块借元素；若后一块也少于 $\lfloor N/2\rfloor$，则合并两块。

复杂度方面：分裂、合并、块内插入删除均为 $O(N)$；定位到目标块为 $O(M/N)$；因此插入删除为
$$
O\left(N+\frac{M}{N}\right),
$$
查询定位为 $O(M/N)$，空间最坏约 $O(M)$（每块可能只装一半）。当
$$
N=\Theta(\sqrt M)
$$
时，各操作均为 $O(\sqrt M)$。这是少见出现根号复杂度的结构。

课堂给出了一组 200000 次操作的实验结果，块状链表取 $N=128$，元素为 `int`。随机插入、随机删除中，数组约需 $17.898$ 秒、$19.799$ 秒，链表约需 $136.386$ 秒、$198.096$ 秒，块状链表仅约 $0.706$ 秒、$0.725$ 秒；随机查询中数组约 $0.008$ 秒，链表约 $82.117$ 秒，块状链表约 $3.130$ 秒。空间上，数组约 $800024$ 字节，链表约 $3200024$ 字节，块状链表约 $1217592$ 字节。该实验说明：随机插入删除时，链表由于定位慢，性能可能比数组差一到两个数量级；块状链表综合性能较好。

块状链表的思想常用于文本编辑器：每个块存一定数量字符，插入删除只在局部块内进行，减少全局移动。它也与 B 树/B+ 树索引思想相通：每个结点存多个元素，通过局部调整维持平衡。课堂还给出一个练习题：频繁将某段序列翻转并移到末尾，同时穿插查询位置 $P$ 的元素。可用块状链表切块拼接，并用懒标记记录翻转，等到查询或必须输出时再真正翻转，从而避免无效操作。

### 小结与课后自习

线性表是最简单且最常用的数据结构。顺序表适合长度变化不大、随机访问多的场景；链表适合频繁插入删除、长度难以估计的场景，但要注意定位代价、缓存局部性和调试成本。特殊矩阵可不用死记下标换算，而用连续一维空间加指针数组自定义映射。稀疏矩阵应掌握 COO 三元组与前缀和快速转置。静态链表是“逻辑链表、物理数组”，可补全“数组/链表 × 静态/动态”的二维认识。块状链表是数组与链表的混合物，在随机插入删除等综合场景中表现突出。

课后要求自学：101 计划《数据结构》教材 2.5.2 大整数处理，以及 OI Wiki 的高精度计算页面；STL 中 `vector` 与数组、`list` 与链表的对应关系需要掌握。跳表（skip list）课堂未展开，但作为链表的升级索引结构，在高并发场景中应用广泛，建议了解其基本思想和适用条件。

### 第六周评讲：链表与基础实现

本次评讲的主线不是单纯对答案，而是从题目中提炼可迁移的结构与方法：合并链表与拍照体现链表维护相邻关系的作用；最大子矩阵把一维前缀和扩展到二维；位运算计算器迁移第二周表达式求值的框架；螺旋矩阵训练把清楚的规则落实为可靠代码的能力。

#### 合并链表

题意是有 $n$ 个块，每块容量为 $k$，第 $i$ 块已经用了 $a_i$ 个位置。相邻两块的总用量不超过 $k$ 时就可以合并，顺序不变，求最终最少块数。它可以等价转化为：把一个非负序列分成尽量少的连续段，使每段和不超过 $k$。

贪心策略是：维护当前块已用空间 $used$，读入 $a_i$ 时，如果 $used+a_i\le k$，就继续合并；否则新开一块，并令 $used=a_i$。一次扫描即可，时间复杂度 $O(n)$，额外空间 $O(1)$。

贪心正确性的证明要点是“把第一块向右延长”。设贪心首块终点为 $g$，任一最优方案首块终点为 $j$。由于贪心取的是最长可行前缀，所以 $j\le g$。把该最优方案的首块延长到 $g$，删去被吞掉的后续块；被截短的块仍然可以保留，因为 $a_i$ 非负，删掉前缀不会增大总和，所以新方案块数不会增加，仍然最优。对剩余后缀重复该操作，就得到贪心方案。实现中只需维护 `used` 和 `blocks`。

#### 拍照

题目按学号排队，逐个加入第 $i$ 位到场同学，其学号为 $p_i$，身高为 $h_i$。第 $i$ 张照片包含前 $i$ 位到场者，并按学号从小到大排队。美观度定义为所有相邻同学身高差的平方和。需要输出 $n$ 个答案，$n\le 10^6$，不能反复排序或扫描整队。

正向插入的困难在于每次都要找前驱、后继并重算大量信息。使用 `set` 可以 $O(\log n)$ 查询，但总时间 $O(n\log n)$ 在本题规模下不够。关键技巧是**正难则反**：从全员照片开始，按 $p_n,p_{n-1},\dots$ 逆序删除。所有学号 $1\ldots n$ 都在场时，相邻关系可直接确定；之后每次删除 $x$，只有它左右两条边会变化。

记边权
$$w(u,v)=(H[u]-H[v])^2,$$
删去 $x$ 后，若其前驱为 $l$、后继为 $r$，则
$$score' = score - w(l,x)-w(x,r)+w(l,r).$$
用数组模拟双向链表：$R[l]=r$，$L[r]=l$。先按学号存身高，即读入 $p_i$ 后令 $H[p_i]$ 为对应身高，再建立 $1\ldots n$ 的链表。初始化 $score$ 为所有相邻学号边权之和。倒序扫描 $i=n\ldots1$，先令 $ans[i]=score$，再删除 $p_i$ 并更新 $score$。注意边界 $l=0$ 或 $r=n+1$ 时边权为 $0$。时间复杂度 $O(n)$，空间 $O(n)$。易错点是 $H[p_i]$ 的对应关系，以及先转成 64 位再计算平方。

正确性不变量是：处理 $i$ 时，链表恰好包含 $p_1,\ldots,p_i$，$score$ 恰好是这些同学按学号排队后的美观度；删除 $p_i$ 只改变相邻两条边，更新后正好得到第 $i-1$ 张照片。

#### 最大子矩阵

题目要求在 $N\times N$ 整数矩阵中选择非空的连续若干行和连续若干列，使矩形内元素和最大；全负数也要选一个。$N\le100$，元素在 $[-127,127]$。这是上一周一维连续区间最大和的二维扩展。

二维前缀和定义为 $S[i][j]$ 表示第 $1\ldots i$ 行、第 $1\ldots j$ 列的矩形和，则
$$S[i][j]=A[i][j]+S[i-1][j]+S[i][j-1]-S[i-1][j-1].$$
查询第 $t\ldots b$ 行、第 $l\ldots r$ 列的目标矩形和：
$$sum=S[b][r]-S[t-1][r]-S[b][l-1]+S[t-1][l-1].$$
预处理 $O(N^2)$，任意矩形和 $O(1)$。

直接枚举上、下、左、右四条边界，复杂度 $O(N^4)$。$N=100$ 时行区间数为 $N(N+1)/2$，列区间数相同，总矩形数约 $5050^2=25\,502\,500$，可以通过。实现时 $ans$ 不能初始化为 $0$，应设为足够小的值，以保证全负数时仍选择一个元素。

还可以优化到 $O(N^3)$：固定上、下两行，把这两行之间的每一列压成一个数，于是问题转化为一维最大子段和。枚举行区间 $O(N^2)$，每次做 $O(N)$ 的最大子段和，总时间 $O(N^3)$。实现时可固定 `top`，逐步增加 `bottom` 并累加每列和。

#### 位运算计算器

题目中 26 个小写字母各代表一个已知的 32 位无符号整数，表达式只包含字母和 `&`、`^`、`|`，没有括号，长度不超过 $2\times10^5$。优先级为 `&` 最高，`^` 次之，`|` 最低，同级左结合。这里的 `^` 是异或，不能套用第二周乘方的含义。

这道题与第二周“括号算式”的关系是：第二周处理多位数字、括号、四种运算、乘方右结合以及 32 位取模，是更一般的求值；本题只保留基本框架，单个字母直接查表取值，无括号，三种运算均可按同级左结合处理。应迁移的是解析方法：识别操作数、比较优先级、及时归约。

仍然使用两个栈：数字栈 `num` 和运算符栈 `op`。读到字母时，把对应常量压入数字栈；读到运算符 $c$ 时，只要栈顶优先级不低于 $c$，就先计算栈顶运算，直到条件不成立，再把 $c$ 压入符号栈；读完表达式后依次计算剩余运算。样例 `a|b^c&d^e|f` 中，先算 `c&d=0`，再算 `b^0^e=18`，最终为 51。实现上可设 `level['|']=1`、`level['^']=2`、`level['&']=3`，用 `process` 函数完成一次归约。完成率偏低说明第二周讲过的表达式求值方法仍需复习。

#### 螺旋矩阵

题目从左上角开始，按右、下、左、上的顺序填入 $1\ldots nm$。若下一格出界或已经有数字，就顺时针转向。$1\le n,m\le100$，长方形、单行、单列都可能出现。把规则拆成状态：当前行 $x$、当前列 $y$、方向 $d$、当前数字 $value$。

方向数组可取
$$dx=\{0,1,0,-1\},\quad dy=\{1,0,-1,0\},$$
分别对应右、下、左、上；转向为 $d=(d+1)\bmod4$。实现时先写当前格 `a[x][y]=value`；若 `value==n*m` 立即退出；否则计算下一格 `nx=x+dx[d], ny=y+dy[d]`；若越界或 `a[nx][ny]` 已填，则转向并重新计算下一格；最后更新 `x=nx, y=ny`。这样始终沿未填矩形的外边界前进，走完一圈后剩余格子仍是更小的矩形，不会漏格或重复填格。时间复杂度 $O(nm)$，空间 $O(nm)$。

这道题不涉及算法，主要是语法与边界检查。只有一半同学通过，老师提醒提交前用手工小样例检查坐标、方向、转向条件和输出，避免行列混用。

### Lab1 总结与 Lab2 介绍

#### Lab1 成绩与实现要点

Lab1 总分前三名为张家恒、陈元镍、黄沐紫；吞吐量排名第一为黄子卿。吞吐量性能约为：只读 47M ops；80% 读 + 20% 写 37M ops；50% 读 + 50% 写 43M ops；20% 读 + 80% 写 39M ops；1% 读 + 99% 写 38M ops。

第一名采用开放地址法 + SIMD 指令集查找。为节省内存，不使用控制字节，而采用所有数据集中都没有出现的一个 `uint64` 作为空槽标志。哈希函数多使用 `_mm_crc32_u64`，部分使用混淆性较强的其他函数。SIMD 查找的基本流程是：由哈希值定位桶，用 `_mm256_set1_epi64x` 广播目标键，用 `_mm256_load_si256` 加载桶内键，用 `_mm256_cmpeq_epi64` 比较，用 `_mm256_movemask_pd` 得到匹配掩码，再用 `_builtin_ctz` 取第一个匹配位置；若未匹配且遇到空槽则失败，否则继续探查。

其他优化包括：按 64 字节缓存行做内存对齐；使用 huge page 减少页表规模、提高页表缓存命中；用分支预测 hint 减少分支预测失败导致的流水线气泡；使用 `forceinline` 等。老师在总结中强调，这些优化要结合数据结构布局和常数开销理解。

#### Lab2 的新要求与 B+ 树

Lab2 相对 Lab1 增加了区间查找（scan）操作，因此索引需要维护数据有序性。哈希并不适合区间查找，通常要使用平衡树类索引。B+ 树是效率较高、综合性能较好的索引和基准测试结构；红黑树、Splay、B+ 树、基数树等都支持区间查找，但不同平衡树效率差距很大。

B+ 树的内部节点最多有 $m$ 个键值和 $m$ 个子节点；除根节点外，最少有 $m/2$ 个子节点。叶节点包含键值、数据和指向下一叶节点的指针，叶节点按键值从小到大链接。查找时从根节点开始，在节点内通过二分或线性查找选择子节点，一路到叶节点；区间查找先找到最小键所在叶节点，再沿叶链表向后扫描。

插入时先找到应插入的叶节点，在对应位置插入键值和数据。若叶节点键值个数达到 $m$，则分裂，并把分裂节点和分隔值插入父节点；父节点满时继续分裂并向上插入，直到父节点未满，或根节点满时新建根节点。删除时先找到叶节点并删除；若叶节点数据量小于 $m/2$，先尝试向兄弟节点借值，借不到则与兄弟合并，并从父节点减少一个键值，必要时继续向上调整。

B+ 树效率高的重要原因是以较大分支因子 $m$ 降低树高。红黑树是二叉结构，高度约为 $\log_2 n$；B+ 树高度约为 $\log_m n$，访问节点次数更少，不连续内存访问也更少。此外，数据结构本身的代码常数、每个操作的指令数、内存布局都会影响读写效率。课件给出的对比中，红黑树（STL map）单点查找约 623587 ops/s、区间查找约 253485 ops/s、插入约 591233 ops/s；B+ 树分别约为 2502485、1386796、1755778 ops/s。

#### 学习型索引与可插入索引

学习型索引的目标是提供与传统索引类似的功能，包括点查找、区间查找，以及可能的插入、删除和批量加载。对于有序数组 $D=\{(k_0,p_0),(k_1,p_1),\ldots\}$，其中 $k_i$ 为键值、$p_i$ 为地址，希望用机器学习模型 $F$ 拟合映射 $H:K\to P$。传统 B+ 树可看作根据键值区间做决策树；学习型索引则尝试直接学习数据分布，由键值预测位置，从而减少比较。

难点在于很难找到完美拟合数据集的函数。实际中常用多个分段线性函数、较复杂模型，或允许预测位置存在一定误差。PGM 索引的设计是：设有序键值集合为 $Key=\{k_1,k_2,\ldots,k_n\}$，地址为 $1\ldots n$，用 $m$ 个线性函数 $f_i(x)=w_i x+b_i$ 拟合区间 $[l_i,r_i)$，允许最大误差 $E$，即对 $k_i\in[l_i,r_i)$ 有
$$|f_i(k_i)-i|\le E.$$
在预测位置附近误差区间内再做指数查找。拟合约束可写成
$$i-E\le w k_i+b\le i+E,$$
在 $w$-$b$ 坐标系下转化为 $2n$ 条边的半平面交是否存在的问题，可在 $O(n)$ 时间内判断。若加入新边后半平面交不存在，就需要新开一个线性段。得到 $m$ 个线性函数后，再对这些分段函数的最小键递归拟合，形成多层结构。

为了支持插入，PGM 可采用类 LSM 树结构：维护多棵从小到大的 PGM 树，大小按等比数列增长；每次插入最小的树，达到阈值后与下一级更大的树归并并重建索引；查找时同时查找多棵树。这样插入较快，但查找会稍慢。ALEX 索引则在内部节点和叶节点中使用间隙数组，键值放在模型预测位置附近，数组保留空槽；插入位置为空则直接插入，否则移动数据到附近空槽，并通过控制节点数组的密度保证平均插入时间复杂度。

代码的 competitor 中实现了多个学习型索引，如 ALEX、Finedex、LIPP、PGM、XIndex，以及传统索引 ART、Masstree、B+ 树、Wormhole、HOT 等。老师建议学有余力者阅读源码和相关论文。查找文献可使用 Google Scholar、dblp；学校购买了大量文献资源，遇到付费页面可断开 VPN、使用校园网访问。

### 串与串匹配算法

#### 串的定义与匹配问题

设 $V$ 是程序设计语言采用的字符集，由 $V$ 上的字符组成的任何有限序列称为字符串，简称串：
$$s="a_1a_2\cdots a_n"\quad(n\ge0).$$
其中 $s$ 是串名，双引号之间是串值，$a_i\in V$。串中字符数目 $n$ 为串长；长度为 0 的串称为空串。一个串的任意连续子序列称为该串的子串，包含子串的串称为主串。前缀是从串首开始到某个位置结束的特殊子串；后缀是从某个位置开始到串末尾结束的特殊子串；真前缀、真后缀指除串本身外的前缀、后缀。字符在序列中的序号称为该字符在串中的位置；子串在主串中的位置用其第一个字符在主串中的位置表示。

串本质上是线性表，只是元素类型限定为字符；与一般线性表相比，常见操作不同。串的常见操作包括求长度、判空、比较、拼接、删除、查找等，其中字符串匹配是非常重要的操作，也是本课程重点。匹配术语有两套：主串与模式串，或文本串与模式串（text 与 pattern）。给定长度为 $n$ 的文本 $T[1\ldots n]$ 和长度为 $m$ 的模式 $P[1\ldots m]$，$m\le n$。若存在 $0\le s\le n-m$，使得
$$T[s+1\ldots s+m]=P[1\ldots m],$$
则称模式 $P$ 在文本 $T$ 中以偏移 $s$ 出现，$s$ 为有效偏移；否则为无效偏移。匹配问题就是找有效偏移。若要求全部匹配，通常重叠匹配也算。

#### BF 算法

BF（Brute-Force）是最朴素的匹配算法：文本指针与模式指针从头开始逐字符比较；相等则同时后移；失配则模式串整体后移一位，文本指针回溯到本轮起点的下一位，重新比较。代码可写成两层循环，或用一个 `MatchCmp` 函数比较长度为 $m$ 的窗口。

最好情况是文本前 $m$ 个字符与模式匹配，比较 $m$ 次，复杂度 $O(m)$。最坏情况是每次都在最后一位失配，例如 $P=\text{"abc"}$、$T=\text{"aaaaaaaa"}$，模式串的 $m$ 个字符要与文本块比较 $n-m+1$ 次，共 $m(n-m+1)\le mn$ 次，复杂度 $O(mn)$。

BF 的优点是简单、好写、无预处理、额外空间少，而且滑动窗口内从前往后或从后往前比较都可以。缺点是效率不理想，主要有两个原因：一是窗口内逐个字符比较；二是失配后文本指针回溯，前一次匹配得到的信息被丢弃。KMP 从“失配后少移动、利用已有信息”入手，KR 从“把模式串看成一个整体、用哈希过滤”入手，BM 则从“从右向左比较、利用坏字符和后缀信息大跨度跳跃”入手。

#### KR 算法

KR（Karp-Rabin）算法把模式串看成一个整体，计算其哈希值，再计算文本中每个长度为 $m$ 的滑动窗口的哈希值。先比较哈希值：若哈希值不相等，则两个串一定不相等，可以直接跳过；若哈希值相等，再逐字符验证是否真正匹配。由于哈希是单向的，哈希值相等不保证串相等，因此需要验证。

关键是滑动窗口哈希要能在 $O(1)$ 时间内更新。常用做法是取一个大整数 $Q$ 作为模数，或直接把字符串看作二进制/多进制数后截取后若干位。实践中常取二进制后 16 位、32 位或 64 位，因为机器一次运算即可完成，简单且有效。设窗口从 $T_1$ 移到 $T_2$，只需去掉最高位、补入最低位并重新取模；若每次重新计算 $O(m)$，就退化为暴力比较，没有意义。

KR 的预处理时间为 $O(m)$，最好情况下每次哈希都准确过滤，匹配时间为 $O(n)$，总时间 $O(n+m)$；最坏情况下哈希冲突频繁，每次都验证，退化为 $O(mn)$。哈希函数选取会显著影响效率。老师指出，随机数据下 KR 并不一定优于最简单的 BF，但在某些场景下与 BM 接近，仍是有竞争力的方法。

#### KMP 算法

KMP 由 Knuth、Morris、Pratt 共同提出。历史上，Cook 在 1970 年研究抽象机时证明最坏情况下模式匹配可在 $O(n+m)$ 时间内完成；Knuth 和 Pratt 据此构造方法；Morris 在开发文本编辑器时为了避免检索回溯也独立得到同样算法；1977 年三人共同正式发表。KMP 的核心是：失配时主串指针不回溯，而是利用模式串自身的最长真前缀与真后缀相等的信息，决定模式串应跳到哪个位置。

设当前文本位置为 $i$，模式位置为 $j$，且 $T[i-j\ldots i-1]=P[0\ldots j-1]$ 已经匹配成功，但 $T[i]\ne P[j]$。朴素算法会把模式后移一位；但若 $P[0\ldots j-2]\ne P[1\ldots j-1]$，则后移一位后仍然不匹配，可以直接跳过。不断寻找最大的 $k<j$，使得
$$P[0\ldots k-1]=P[j-k\ldots j-1],$$
则可以直接把模式串的 $P[k]$ 与 $T[i]$ 比较。这个 $k$ 就是 `next[j]`。

`next` 数组的含义有两层：第一，`next[j]=k` 表示当前字符 $P[j]$ 之前的子串 $P[0\ldots j-1]$ 中，最大长度为 $k$ 的相同真前缀和真后缀；第二，失配时模式串应跳到位置 $k$。若 `next[j]=0` 或 `-1`，则跳到模式串开头；若 `next[j]=k>0`，则跳到 $k$ 位置继续比较。形式化地，当 $j=0$ 时 `next[j]=-1`；否则
$$
next[j]=\max\{k\mid P[0..k-1]=P[j-k..j-1],\ k<j\},
$$
若不存在这样的 $k$，则 `next[j]=0`。

例如模式串 `ABCDABD` 各前缀的最大公共真前后缀长度为：`A:0`、`AB:0`、`ABC:0`、`ABCD:0`、`ABCDA:1`、`ABCDAB:2`、`ABCDABD:0`。由此得到 `next` 数组 `[-1,0,0,0,0,1,2]`。匹配时若在 `ABCDAB` 后的 `D` 处失配，已知前面 `AB` 与开头 `AB` 相同，就可以把模式串跳到对应位置，从 `C` 继续比较，而不必回退主串。

KMP 匹配代码的框架是：`i` 指向文本，`j` 指向模式；若 `t[i]==p[j]`，则 `i++,j++`；否则若 `next[j]!=-1`，令 `j=next[j]`，主串位置不变；否则说明模式第一位就失配，令 `i++, j=0`。匹配成功时返回 `i-m`。时间复杂度 $O(n+m)$，额外空间 $O(m)$。

#### next 数组的求法与优化

求 `next` 的关键是递推。设已经知道 `next[0..i]`，现在要求 `next[i+1]`。令 $k=next[i]$，它表示 $P[0\ldots i-1]$ 的最长相等真前后缀长度为 $k$，即前 $k$ 个字符与后 $k$ 个字符相等，记作 $A_1=A_2$。现在比较 $P[i]$ 与 $P[k]$：

- 若 $P[i]=P[k]$，则两个相等前后缀各延长一位，得到长度 $k+1$，所以 `next[i+1]=k+1`。
- 若 $P[i]\ne P[k]$，则不能直接延长 $A_1,A_2$，需要寻找次长的相等前后缀。由于 $A_1=A_2$，其中还包含更短的相等前后缀 $B_1=B_3$，而 $B_1$ 的下一位位置正是 `next[k]`，所以令 $k=next[k]$，继续比较。
- 若 $k=-1$，说明没有可延长的前后缀，令 `next[i+1]=0`。

代码可以写成：
```cpp
next[0] = -1;
int i = 0, k = -1;
while (i < m - 1) {
    if (k == -1 || p[i] == p[k])
        next[++i] = ++k;
    else
        k = next[k];
}
```
这里把 `k==-1` 和 `p[i]==p[k]` 合并，因为 `k=-1` 时执行 `next[++i]=++k` 恰好得到 `next[i+1]=0`。老师强调，不一定要背这几行代码，而应掌握“分情况讨论、递推利用已知 next 值”的方法论。

`next` 还可以优化。若失配时 $P[j]=P[next[j]]$，那么下一次比较仍会失败，因为文本当前位置的字符就是 $P[j]$。因此当 $P[i]=P[next[i]]$ 时，应继续递归，令
$$next[i]=next[next[i]],$$
直到两者不等或到达边界。这样可减少无意义的二次失配。KMP 还可扩展到多次匹配、树上匹配和多模式匹配；AC 自动机就是把多个模式串组织成树并在树上跑 KMP 的典型结构。虽然单独使用时 KMP 在实际中常不如 BF/BM，但在树上多模式、嵌入式短代码、严格线性保证等场景仍有不可替代的价值。

#### BM 算法

BM 由 Boyer 和 Moore 于 1974 年提出，1977 年正式发表。其核心突破是**从右向左匹配模式串**。传统算法习惯从左向右，但 BM 必须从右向左，才能利用“坏字符”信息进行大跨度跳跃。

**坏字符规则**：当从右向左比较时，第一个不匹配的字符称为坏字符。设模式串当前比较位置下标为 $j$，坏字符 $x$ 在模式串中最后出现的位置为 `last[x]`，则右移位数
$$shift=j-last[x].$$
若 $x$ 不在模式串中，则令 `last[x]=-1`，相当于在 $P[-1]$ 放了一个万能匹配符，使坏字符与模式串头部的下一个位置对齐；若计算出的 `shift<0`，说明会向左移动，必须修正为 1，以避免死循环。

例如文本 `HERE IS A SIMPLE EXAMPLE`、模式 `EXAMPLE`，第一次从右向左比较时坏字符 `S` 不在模式中，可以直接把模式串跳过整段，使 `S` 与 `P[-1]` 对齐；之后坏字符 `P` 在模式中，则右移使坏字符与模式串最右的 `P` 对齐。字符集越大，坏字符不在模式中或只出现很少的概率越高，跳跃越大，平均性能越好，最好情况可达 $O(n/m)$。

但只使用坏字符规则时，最坏情况仍可能退化为 $O(mn)$，例如文本和模式都由大量相同字符构成。**好后缀规则**利用已经匹配成功的后缀 $u=P[j+1\ldots m-1]$，在模式串中寻找该后缀的其他出现，或寻找与后缀的前缀相匹配的部分，计算 GS 表，表示每个位置失配后的右移步长。每一步同时计算坏字符规则和好后缀规则的移动量，取较大者。好后缀规则不仅能在很多情况下跳得更远，还能保证最坏情况为线性时间。

BM 的预处理时间与空间为 $O(m+|\Sigma|)$，其中 $|\Sigma|$ 为字符集大小。最好情况 $O(n/m)$，最坏情况在加入好后缀规则后为 $O(n+m)$。实际中 BM 通常比 KMP 快 3 到 4 倍，是系统库中广泛采用的字符串匹配算法。若只找第一次匹配，BM 已很高效；若要找全部匹配，原始做法在匹配成功后从文本下一位置重新开始后缀匹配，最坏可退化到 $O(mn)$，例如模式 `AAA`、文本 `AAAAA...`。Galil 在 1979 年补充规则，利用之前匹配成功的信息，使多次匹配也能达到线性。

#### 实验比较与结论

老师展示了两组实验。第一组 Task1～Task3 中，文本串长度为 $10^6$，模式串长度在 $10$ 到 $40$ 之间随机，测试 5000 组，字符等概率随机生成。Task1 字符集大小 26；Task2 字符集大小 4，模拟生物 ACTG；Task3 字符集大小 255。结果为：

| 任务 | BF | BM | KMP |
|---|---:|---:|---:|
| Task1 | 9.097s | 2.214s | 16.228s |
| Task2 | 30.772s | 11.957s | 39.129s |
| Task3 | 4.830s | 1.743s | 11.245s |

Task4 字符集大小为 2，且 `a:b` 出现概率为 99:1，模式长度 100～400，测试 5000 组；Task5、Task6 模拟真实文本，分别取《独立宣言》和 BM 论文，随机生成模式串。结果中 BM 均为最优；除 Task4 外，KMP 都没有跑过暴力算法 BF。Task4 中 KMP 为 17.903s、BF 为 208.135s，KMP 优于 BF，但 BM 仍以 4.79s 最快。

第二组实验使用 SARS-CoV-2 DNA 序列数据，长度约 30000，通过数据增强得到约 3000000 个只含 ATGC 的字符串。结果表明，BM 搜索器比朴素算法快约 4.01 倍；O2 优化对实验结果影响很大。寻找全部匹配时，用 `aaab` 重复构造数据，未加 Galil 优化的 BM 会退化，而 KMP、KR 和优化后的 BM 在最坏情况下均为线性；随机数据下 BM 的期望复杂度为 $O(n/m)$，因此效率很高。

这些实验说明：理论复杂度重要，但不能只看复杂度。KMP 有完美的线性最坏复杂度，但常数和预处理可能使其在实际中不如 BF；BM 在真实数据中通常最好，尤其字符集大时优势明显；BF 简单无预处理，在小规模或某些实际数据中很有竞争力；KR 用哈希过滤，在部分场景可与 BM 接近。好的学术分析应结合理论证明与实验验证，并能解释二者不一致的原因。

#### 栈、队列与单调结构预告

下次课将快速复习栈和队列，并重点讲单调栈、单调队列。课堂讨论了“两个栈实现队列”：设入栈 `in` 和出栈 `out`，入队时压入 `in`；出队时若 `out` 为空，就把 `in` 中元素全部倒入 `out`，再从 `out` 弹出。每个元素最多被倒入一次，均摊时间复杂度 $O(1)$。

“栈在 $O(1)$ 时间内维护最大值”的做法是使用辅助栈：主栈正常压入、弹出；辅助栈同步压入当前最大值，即新元素与辅助栈顶取较大者。弹出时两个栈同步弹出，任意时刻辅助栈顶就是当前主栈的最大值。老师还指出，“两个队列实现栈”没有很优雅的做法，只能用较笨的方法：每次出栈时把前 $n-1$ 个元素移到另一个队列，弹出最后一个元素；这可以作为一般解，但不如两个栈实现队列优雅。

### 作业与机考题目讲评

#### 题目一：连续平方和与预处理查表

题目给定平方数 \(K\)，\(K\le 10^{18}\)，最多 \(10^4\) 次询问，判断是否存在正整数 \(n\)，使得
\[
1^2+2^2+\cdots+n^2=K.
\]
记
\[
F(n)=\frac{n(n+1)(2n+1)}{6}.
\]
由 \(F(n)>n^3/3\) 可知，当 \(K\le 10^{18}\) 时，可能的 \(n\) 至多约为 \(2\times 10^6\)，候选数量很小。因此不需要对每次询问单独枚举，而是先预处理所有不超过上界的 \(F(n)\)，将其存入数组或有序表；询问时二分查找 \(K\) 是否在表中。

核心代码思想是：从 \(n=1\) 开始累加 \(n^2\)，一旦超过 \(10^{18}\) 就停止，把每个前缀和加入表；之后每次读入 \(K\)，用二分查找判断是否存在。时间复杂度约为 \(O(\sqrt[3]{K}+Q\log \sqrt[3]{K})\)，空间复杂度为 \(O(\sqrt[3]{K})\)。题目输出较特殊：若存在则输出 `Fake news!`，否则输出 `Nobody knows math better than Mr.Trump`。

#### 题目二：求解 next 数组

本题是 KMP 中 `next` 数组的模板题：给定长度 \(n\le 10^6\) 的字符串，输出每个前缀的 `next` 值。`next[i]` 表示前缀 \(s[1..i]\) 的最长相等真前后缀长度，整个前缀自身不能计入。例如
\[
\texttt{abcabcd}\rightarrow 0,0,0,1,2,3,0.
\]
计算时利用递推：先尝试把 `next[i-1]` 延长一位；若失配，则沿 `next` 链回退，直到可以匹配或回到 0。该题较为基础，重点在于理解 `next` 的定义与回退过程。

#### 题目三：周期循环与 border 链

题目要求向字符串末尾补最少的字符，使其成为某个非空子串的整数次重复，且至少重复两次。例如 `ppp` 已经满足条件，补 0 个；`pip` 可补成 `pipi`，补 1 个；`machinelearning` 需要补 15 个。

关键转化是：若字符串长度为 \(n\)，周期长度为 \(p\)，则 \(b=n-p\) 是原串的一个 border，即长度为 \(b\) 的前缀与后缀相等。因此枚举周期等价于枚举 border。所有 border 可以通过从 `next[n]` 开始不断跳 `next` 得到：
\[
b=next[n],\ next[next[n]],\ \ldots,\ 0.
\]
对每个 border \(b\)，周期为 \(p=n-b\)。固定周期 \(p\) 后，需要把原串补到至少重复两次的整数倍长度，补字符数为
\[
\max\left(2,\left\lceil \frac{n}{p}\right\rceil\right)p-n.
\]
其中取 \(\max(2,\cdot)\) 是为了保证至少重复两次；否则可能只重复一次，得到不合法答案。对所有候选周期取最小值即可。每组询问时间复杂度 \(O(n)\)，空间复杂度 \(O(n)\)。

需要特别注意：最短周期不一定对应最少补齐量。反例为
\[
s=\texttt{aabaabaaabaabaa},\quad n=15.
\]
全部周期为 \(7,10,13,14,15\)，对应补齐量分别为 \(6,5,11,13,15\)，最优为 5。周期 7 的循环节是 `aabaaba`，需要重复 3 次到 21 位，补 6 个；周期 10 的循环节是 `aabaabaab`，重复 2 次到 20 位，补 5 个。若只看 \(p=n-next[n]\)，就会漏掉更优候选。因此必须沿 `next` 链枚举全部 border。

#### 题目四：重复字符串与不重叠 border

题目给定长度 \(n\le 5000\) 的字符串，求最长的两次不重叠相同子串。样例 `strangeorange` 中，`range` 出现在位置 \(3..7\) 和 \(9..13\)，答案为 5。

一种 KMP 思路是枚举第一次出现的起点，将后面的串记为 \(t\)，只考察以该位置开头的后缀。若第二次出现的前缀长度为 \(j\)，则两段相同等价于该前缀存在长度为 \(j\) 的 border，并且要求不重叠：
\[
2j\le len.
\]
直接对每个后缀重新求最长 border 会较慢。可以持续维护一个状态 \(j\)，表示当前满足长度限制的最长不重叠 border。计算时仍使用标准 KMP 的 `next` 跳转表：遇到失配沿 `next` 回退，匹配则 \(j\) 加一；若 \(2j>len\)，再沿 `next` 回退直到不重叠。每次用当前的 \(j\) 更新答案。

代码框架如下：
```cpp
int j = 0;
for (int len = 2; len <= m; ++len) {
    while (j > 0 && t[len] != t[j + 1]) j = nxt[j];
    if (t[len] == t[j + 1]) ++j;
    while (2 * j > len) j = nxt[j];
    answer = max(answer, j);
}
```
该做法总时间为 \(O(n^2)\)，空间为 \(O(n)\)。正确性在于：当前合法 border \(b\) 去掉末尾字符后得到上一步的 \(b-1\)，它仍然不重叠，因此一定能从旧的 \(j\) 沿 `next` 链找到；保留最长可延长候选，再剔除重叠，得到新的最长合法值。摊还分析上，\(j\) 的总增长量限制了全部回退次数。

另一种更直观的思路是枚举切分位置，将后半段、一个未出现过的分隔符、前半段拼接后跑 KMP。末尾位置的 `next` 值会给出后半段与前半段相等部分的最长长度，从而更新答案。这种方法利用了 KMP 做字符串匹配的思想，理解起来更直接。

#### 题目五：由 next 数组反向构造字符串

题目给定 \(n\le 10^5\) 个 `next` 值，要求构造一个整数序列，使得重新计算 `next` 后与输入逐项完全一致。题目保证有解，可使用任意整数，输出任意合法答案。

构造规则非常简洁：若 `next[i]=0`，说明当前位置不能与前面形成非空 border，此时填入一个从未出现过的新整数；若 `next[i]>0`，则必须满足第 \(i\) 位与第 `next[i]` 位相等，因此直接令
\[
s[i]=s[next[i]].
\]
代码只需维护一个 `fresh` 计数器：
```cpp
int fresh = 0;
for (int i = 1; i <= n; ++i) {
    int b; cin >> b;
    if (b == 0) s[i] = ++fresh;
    else s[i] = s[b];
}
```
其正确性来自等价关系：`next[i]=k` 蕴含 \(s[i]\) 与 \(s[k]\) 相等，并且更早的前后缀关系由已有 `next` 保证。若 `next[i]=0` 却填入新字符，不会破坏已有关系；若未来出现跨过该位置的 border，则会推出当前位置存在非零 border，与 `next[i]=0` 矛盾。该构造只连接了最少的等价关系，因此若原 `next` 有解，则此构造必有解。时间与空间均为 \(O(n)\)。

### 栈与队列

#### 栈的基本概念与实现

栈是操作受限的线性表，只允许在栈顶进行插入和删除，满足后进先出（LIFO）。栈底固定，栈顶随操作移动。基本操作包括进栈 `push`、出栈 `pop`、取栈顶 `top`、判空 `isEmpty`、判满 `isFull`。用数组实现时，通常设置 `top=-1` 表示空栈；进栈时 `stk[++top]=x`，出栈时取 `stk[top--]`。C++ 模板类中还可加入最大容量 `MAXN`，在 `push` 前判断 `top>=MAXN-1`，在 `pop` 前判断 `top==-1`。

STL 中 `pop` 通常只删除元素而不返回被删值，取栈顶需要另用 `top()`。这与部分旧教材中“`pop` 同时返回元素”的写法不同。两种写法都可工作，但需要区分接口语义。

#### 两栈共享与多栈共享

若两个栈的总元素数不超过 \(N\)，可让两个栈共用一个长度 \(N\) 的数组：栈 1 的栈底在左端，栈 2 的栈底在右端，两个栈顶向中间伸展，直到相遇才溢出。这样可提高空间利用率，避免为每个栈单独开 \(N\) 个空间造成浪费。

若扩展到 \(K\) 个栈，且所有栈中元素总数不超过 \(N\)，可用静态链表管理共享空间。其思想是：把所有可用结点组织成空闲链表或空闲队列；每个栈维护自己的链头；入栈时从空闲结构中取一个结点挂到对应栈顶，出栈时把结点归还空闲结构。由于每个栈逻辑上是链式栈，物理存储可放在同一个数组中，所以总空间仍为 \(O(N)\)，另加少量栈头与空闲管理信息。静态化还能增强缓存局部性，在现代计算机上往往比动态链表更快。链式栈的栈顶设在链头，进栈出栈都在链头完成，只要内存有空间就不会出现顺序栈的“队满”问题。

### 表达式求值

#### 三种表示与后缀表达式计算

表达式由操作数、操作符和分界符组成。常见表示有三种：中缀表示如 \(A+B\)，操作符在操作数中间；前缀表示如 \(+AB\)，操作符在前；后缀表示如 \(AB+\)，操作符在后。人类习惯中缀表达式，需要处理优先级、括号和结合性；而后缀表达式已经体现了运算顺序，不含括号，也不需要优先级，因此更适合计算机求值。

后缀表达式计算使用一个栈：从左到右扫描，遇到操作数就入栈；遇到运算符就弹出两个操作数，先弹出的是右操作数，后弹出的是左操作数，计算后将结果压回栈中。例如
\[
a+b*(c-d)-e/f
\]
对应后缀表达式
\[
abcd-*+ef/-.
\]
扫描过程中按上述规则逐步归约，最终栈中剩下的数即为结果。

#### 中缀转后缀的算法

转换时使用一个操作符栈，并设置结束符 `$`。初始化时将 `$` 入栈；从左到右读中缀表达式：
- 遇到操作数直接输出；
- 遇到左括号 `(` 入栈；
- 遇到运算符时，比较当前运算符的栈外优先级与栈顶运算符的栈内优先级。若当前优先级小于等于栈顶优先级，则弹出栈顶并输出，直到当前优先级大于栈顶，再让当前运算符入栈；
- 遇到右括号 `)`，依次弹出并输出运算符，直到遇到左括号；左括号弹出但不输出；
- 遇到结束符 `$`，弹出所有运算符并输出，`$` 不输出。

例如处理 \(a+b*(c-d)-e/f\) 时，乘号遇到加减号会先入栈，右括号会弹出括号内运算符，同级运算符按左结合先弹出先到者。对于指数运算 `^`，它是右结合，不能简单按左结合处理；可以在比较时特判，或把栈内优先级设得比栈外低，使后面的指数不提前弹出。讲师强调：遇到复杂情况就分情况讨论，用覆盖面较全的例子逐一验证，比死记规则更可靠。

### 迷宫问题与搜索回溯

迷宫可用二维数组 `maze[m+2][n+2]` 表示，外围加一圈墙，`1` 表示墙，`0` 表示通路。任一时刻位置用坐标 \((i,j)\) 表示，并设置 8 个可能方向的方向表。搜索时用栈保存状态 `(x,y,d)`，其中 `d` 表示当前已经探索到第几个方向；同时用 `mark` 数组标记已访问位置，避免死循环。

算法从入口开始，按顺时针方向尝试；若某方向可走且未访问，则标记并前进，同时把当前状态压栈；若所有方向都走不通，则出栈回溯到上一个状态，继续尝试其下一个方向。若到达出口，则栈中保存的路径可依次输出。该过程本质上是深度优先搜索，栈中不仅保存坐标，还要保存“已经探索到哪个方向”，否则回溯后无法继续。课后应阅读教材代码，理解其变量命名较差但逻辑正确的实现，并尝试改写成递归形式。

### 队列

#### 顺序队列与循环队列

队列是先进先出（FIFO）的线性表，队尾进队，队头出队。若用普通数组实现，随着出队操作，队头前面会留下无法利用的空位，造成“假溢出”。解决办法是把数组逻辑上看成环，使用循环队列。循环队列中进队和出队都要对下标取模：
\[
rear=(rear+1)\bmod size,\quad front=(front+1)\bmod size.
\]
常用判空条件为 `front==rear`。若直接判满也会得到 `front==rear`，无法区分空和满。教材常用方案是空出一个格子，判满条件为
\[
(rear+1)\bmod size==front.
\]
另一种方案是额外维护计数器 `count`，空时 `count=0`，满时 `count=size`，这样所有格子都能使用。双端队列允许两端进出，灵活性更高，兼具栈和队列的部分功能。

#### 链式队列与优先级队列

链式队列队头在链头，队尾在链尾；进队时只要内存有空间就不会队满，队空条件为 `front==NULL`。优先级队列每次选择优先级最高的元素出队，常用于调度。优先级一般用数字表示，数字越小优先级越高；若最高优先级有多个元素，则按它们在队列中的先后顺序出队。简单实现可在出队时扫描整个队列找最高优先级，复杂度 \(O(n)\)；更高效的实现通常用堆，后续课程会讲。杨辉三角也可借助队列逐行生成：每行首尾为 1，中间元素由上一行相邻两个元素相加得到。

### 单调栈

#### 基本思想与 MinStack

单调栈不是新的数据结构，而是用栈维护一组单调递增或单调递减的值。栈中可存值，也可存下标；存下标能同时获得值和位置信息，因此更通用。以维护栈中最小值为例，辅助单调栈存主栈下标：入栈时，若辅助栈为空或新元素小于当前最小值，则把新下标压入辅助栈；出栈时，若辅助栈顶等于主栈栈顶下标，则同步弹出；`getMin()` 返回辅助栈顶对应的主栈元素。这样最小值查询为 \(O(1)\)。

#### 左边第一个更大元素

求每个数左边第一个比它大的元素，可维护单调递减栈。扫描到 \(x\) 时，先把栈中所有小于等于 \(x\) 的元素弹出，此时栈顶就是左边第一个比 \(x\) 大的元素；若栈空则不存在。每个元素最多进栈、出栈一次，因此总时间复杂度 \(O(n)\)。

类似地：左边第一个更小用单调递增栈；右边第一个更大可从右往左扫描并维护单调递减栈；右边第一个更小可从右往左扫描并维护单调递增栈；最近更大可左右各做一次取更近者。若要求最远更大，可在单调栈基础上利用栈的线性表性质进行二分查找，不能只把单调栈理解为“只能在栈顶操作”的封闭结构。

#### 接雨水

接雨水问题给定崎岖路面高度，求积水面积。单调栈按横向分层计算：维护一个存下标的单调递减栈。当遇到高度不低于栈顶的高度时，弹出低处，若栈非空，则当前高度与新的栈顶高度取较小值作为高处高度，低处高度为刚弹出的高度。宽度为
\[
i-st.top()-1,
\]
增加面积为
\[
(i-st.top()-1)\bigl(\min(h[i],h[st.top()])-h[low]\bigr).
\]
每个下标进出栈一次，总时间 \(O(n)\)。该题有多种线性解法，单调栈方法是较纯粹但也较难第一次想到的解法。

### 单调队列

#### 滑动窗口最大值

单调队列用队列维护单调性，典型应用是滑动窗口最大值。队列中存下标，保持对应值单调递减。处理新元素 \(a[i]\) 时，先弹出队尾所有小于等于 \(a[i]\) 的元素，再将 \(i\) 入队；若队头下标已经不在当前窗口 \([i-k+1,i]\) 内，则弹出队头。此时队头就是当前窗口最大值。每个元素最多入队、出队一次，总时间 \(O(n)\)。

#### 二维子矩阵最大值

给定 \(n\times n\) 矩阵，求所有 \(m\times m\) 子矩阵中的最大值。暴力枚举每个子矩阵并扫描其中元素，复杂度很高。优化方法是先对每一行做长度为 \(m\) 的滑动窗口最大值，得到临时矩阵 `temp`；再对 `temp` 的每一列做长度为 \(m\) 的滑动窗口最大值，得到答案矩阵。两次单调队列将复杂度降为 \(O(n^2)\)（在矩阵为 \(n\times n\)、窗口固定为 \(m\) 的设定下）。其核心观察是：同一行中的最大值会被多个子矩阵重复使用，先预处理可消除重复计算。

### 小结

栈和队列都是操作受限的线性表。栈适合后进先出、表达式求值、递归模拟和深度优先搜索；队列适合先进先出、层次遍历和广度优先搜索。顺序队列必须用循环队列才能有效利用空间，链式队列则没有固定容量限制。优先级队列按优先级出队，常见高效实现是堆。单调栈与单调队列通过维护元素的单调性，把许多“找某个方向第一个更大/更小”“滑动窗口最值”“二维区间最值”问题从平方级优化到线性或平方级；判断是否使用时，可看问题中是否同时隐含“越近/越远”和“越大/越小”两种优先级。其复杂度分析通常只需统计每个元素进入和离开栈或队列的次数。

### 第八周题目评讲：单调栈主线

本周五道题虽然表面场景不同，但核心都围绕**单调栈**以及“元素作为某种极值时的贡献范围”展开。单调栈的基本结构是：栈中存放**下标**，对应的高度保持单调；新元素入栈前，先弹出破坏单调性的栈顶。对每个被弹出的下标 $j$，新元素 $i$ 往往是 $j$ 右侧第一个更大或更小的位置；弹出后的新栈顶则是 $j$ 左侧第一个更大或更小的位置。每个下标至多进栈、出栈各一次，因此即使外层循环内套 `while`，总时间复杂度仍为 $O(n)$。这一摊还分析与“每个元素总减少量不超过总增加量”的思想一致。

#### 接雨水

题意是给定 $n$ 根宽为 $1$ 的柱子，高度为 $a[i]$，下雨后求柱子之间最多能接多少水。最直接的想法是**按列计算**：第 $i$ 列的水位由左右两侧最高柱中较矮者决定，即

$$
\text{water}_i=\min(\text{leftMax}_i,\text{rightMax}_i)-a[i]
$$

若该值为负则取 $0$。逐列向两边扫描的复杂度为 $O(n^2)$，在 $n\le 10^5$ 时不可行。

单调栈采用**按层补矩形**的视角。栈中维护的是尚未遇到足够高右墙的“左墙”下标，对应高度不增。当新柱 $i$ 高于栈顶 `bottom` 时，`bottom` 就是当前坑底；弹出 `bottom` 后，新的栈顶 `left` 是左墙。若弹出后栈为空，说明左侧没有墙，这一层水会流走，不能计入答案。否则本层补上的水量为

$$
(i-left-1)\times \big(\min(h[left],h[i])-h[bottom]\big)
$$

其中宽度是左右墙之间的列数，高度是左右墙较矮者与坑底的高度差。代码框架为：

```cpp
for (int i = 0; i < n; ++i) {
    while (!st.empty() && h[st.back()] < h[i]) {
        int bottom = st.back();
        st.pop_back();
        if (st.empty()) break;
        int left = st.back();
        long long width = i - left - 1;
        long long height = min(h[left], h[i]) - h[bottom];
        water += width * height;
    }
    st.push_back(i);
}
```

样例 `0 1 0 2 1 0 1 3 2 1 2 1` 的每列水量为 `0 0 1 0 1 2 1 0 0 1 0 0`，合计 $6$。本题数据范围下答案上界约为 $10^9$，使用 `long long` 更稳妥。

#### 每个窗口内最小的 $k$ 个数之和

题目“有天你飞起来去摘那云彩”要求：对每个长度为 $m$ 的窗口，选出其中最小的 $k$ 个数并求和，共输出 $n-m+1$ 个答案。若每个窗口都排序，复杂度为 $O(nm\log m)$，不可行。相邻窗口只相差“进一个、出一个”，因此需要维护一个支持动态插入、删除并快速求最小 $k$ 个元素和的结构。

标准做法是**对顶堆**：维护两个堆或两个平衡结构，`low` 保存当前窗口中最小的 $k$ 个数，`high` 保存其余 $m-k$ 个数，并始终保证

$$
\max(low) \le \min(high)
$$

插入新元素 $x$ 时，若 $x$ 小于 `low` 的最大值，则放入 `low`，否则放入 `high`；随后通过 `balance` 调整两堆大小，使 `low` 恰有 $k$ 个元素。`balance` 只搬动堆顶，因此分界关系仍然保持。删除元素可采用**懒删除**：用计数或标记判断元素是否已经离开窗口，读取堆顶前先把已出窗的元素弹出。每个元素至多被搬动一次，总复杂度为 $O(n\log n)$，空间 $O(n)$，答案用 `long long`。

样例 `1 3 4 2 5 6`，$m=4,k=3$：窗口 `[1,3,4,2]` 最小三数和为 $1+2+3=6$；窗口 `[3,4,2,5]` 为 $2+3+4=9$；窗口 `[4,2,5,6]` 为 $2+4+5=11$。

#### 木桶效应

题意：有 $n$ 块木板，对每个 $x=1,\dots,n$，求所有长度为 $x$ 的连续段中“段内最小值”的最大值。也就是每个长度下，最短板的最大容量。直接对每个长度滑窗求最小值是 $O(n^2)$。

反向思考：**枚举每块板作为最短板**，看它能向左右扩展到多宽。固定 $j$，向左找第一个比 $a[j]$ 短的位置 $L[j]$，向右找第一个比 $a[j]$ 短的位置 $R[j]$，则任何包含 $j$ 且落在 $(L[j],R[j])$ 内的连续段，其最短板都是 $a[j]$，该板能支撑的最大长度为

$$
len[j]=R[j]-L[j]-1
$$

于是用 $a[j]$ 去更新 `best[len[j]]`。由于长度具有单调性：若某长度 $x$ 存在容量 $v$，则更短长度也能取到不小于 $v$ 的容量，因此最后从大到小做后缀最大值：

$$
best[x]=\max(best[x],best[x+1])
$$

单调栈实现时，维护高度严格递增的栈；新板 $i$ 弹出所有高度不小于 $a[i]$ 的板 $j$，此时 $i$ 是 $j$ 右侧第一个更短的位置，弹出后的栈顶是 $j$ 左侧第一个更短的位置。代码中常设哨兵 $a[0]=-1$ 保证栈底不被弹出，设 $a[n+1]=0$ 使最后全部弹空。样例 `9 2 7 3 5 6 4 8 7 1` 的结果为 `9 7 4 4 4 3 3 2 2 1`。

#### 跑酷

题意：只能从左往右跳，$i\to j$ 合法当且仅当满足以下之一：

1. 相邻，即 $j=i+1$；
2. 中间的楼都比两端矮，即 $\max(a[i+1..j-1])<\min(a[i],a[j])$；
3. 中间的楼都比两端高，即 $\min(a[i+1..j-1])>\max(a[i],a[j])$。

求从 $1$ 号楼到 $n$ 号楼的最少跳跃次数。设 $dp[j]$ 为到达 $j$ 的最少次数，则

$$
dp[1]=0,\qquad dp[j]=\min\{dp[i]+1:i\to j\text{ 合法}\}
$$

直接枚举 $i$ 并判断区间最值为 $O(n^2)$。利用单调栈可以只枚举真正合法的起点。

以条件②为例，维护高度不增的栈 `high`。处理 $j$ 时，先令 $dp[j]=dp[j-1]+1$ 表示相邻跳。然后当 $h[high.back()]<h[j]$ 时不断弹出 $x$。弹出 $x$ 后，若栈非空且 $h[high.back()]>h[x]$，则说明从 `high.back()` 跳到 $j$ 时，中间楼都比两端矮，可用

$$
dp[j]=\min(dp[j],dp[high.back()]+1)
$$

更新。这里检查的是 $h[high.back()]>h[x]$，而不是简单与 $h[j]$ 比较；因为最后一次弹出后栈顶可能比 $x$ 高，而中途某些栈顶虽然比 $h[j]$ 矮，却可能比 $h[x]$ 高，仍属于合法起点。条件③完全对称，用高度不减的栈 `low` 处理。样例 `1 4 3 2 6 5 7` 的最优路径为 $1\to4\to5\to7$，答案为 $3$。

#### 子串差距和

题意：定义 $f(l,r)$ 为区间最大值减最小值，对所有子数组求和。将最大值部分与最小值部分分开统计：

$$
\sum_{l\le r} f(l,r)=\sum_{l\le r}\max(l,r)-\sum_{l\le r}\min(l,r)
$$

先考虑最大值贡献。固定 $a[j]$，找左侧第一个比它大的位置 $L[j]$，右侧第一个比它大的位置 $R[j]$。若假设元素互不相同，则 $a[j]$ 作为最大值的区间左端点有 $j-L[j]$ 种，右端点有 $R[j]-j$ 种，因此贡献为

$$
a[j]\times (j-L[j])\times (R[j]-j)
$$

最小值部分把“更大”换成“更小”即可。实现时可用一个函数 `contribution(sign)`，通过 `sign` 切换比较方向。

相等元素是关键易错点。为避免重复计数，需要强制每个区间只由某一个相等元素贡献。常用规则是：

- 最大值：左侧找第一个 $>a[j]$，右侧找第一个 $\ge a[j]$；
- 最小值：左侧找第一个 $<a[j]$，右侧找第一个 $\le a[j]$。

这样等号方向一边严格、一边非严格，保证相同元素中只有一个被计入。答案规模可能达到约 $4.5\times 10^{21}$，超过 `long long` 上限，需要使用 `__int128` 输出。该题机考通过人数仅 $6/43$，主要错误集中在等值重复计数和溢出。

### 递归的基本概念与应用

#### 递归的定义

递归通常有两种理解。第一种是**定义式递归**：如果一个对象部分地包含它自己，或用它自己给自己定义，则称该对象是递归的。例如链表结点中的指针指向同类型结点，二叉树、广义表等结构都是递归定义的。第二种是**过程式递归**：如果一个函数直接或间接地调用自己，则称这个过程是递归的。课程主要讨论第二种。

能用递归解决的问题通常具有这样的特征：规模为 $n$ 的问题可以分解为若干规模更小的问题；这些小问题可以继续以同样方式分解；当问题足够小，例如 $n=1$ 或 $n=0$ 时，可以直接求解；最后能由小问题的解方便地构造大问题的解。

递归的典型应用场景有三类：**定义是递归的**，如斐波那契数列、广义表；**数据结构是递归的**，如链表、二叉树；**问题解法是递归的**，如汉诺塔、快速排序。

#### 汉诺塔

汉诺塔有 $A,B,C$ 三根塔座，$A$ 上有 $n$ 个从大到小叠放的圆盘。移动规则是：每次只能移动一个圆盘；圆盘不能离开塔座；任何时刻不能把较大圆盘压在较小圆盘上。目标是把 $A$ 上全部圆盘移到 $B$ 或 $C$，并保持顺序。

递归解法极其简洁：若 $n=1$，直接把 $A$ 移到目标柱；否则先将上面 $n-1$ 个圆盘从 $A$ 移到辅助柱，再把最底下的最大圆盘从 $A$ 移到目标柱，最后把 $n-1$ 个圆盘从辅助柱移到目标柱。代码框架为：

```cpp
void hanoi(int n, char A, char B, char C) {
    if (n == 1) {
        move_disk(A, C);
        return;
    }
    hanoi(n - 1, A, C, B);
    move_disk(A, C);
    hanoi(n - 1, B, A, C);
}
```

最少移动次数为 $2^n-1$。传说中 $64$ 个金盘需要 $2^{64}-1\approx 1.8\times 10^{19}$ 步，即使每秒移动一次也需要约 $5845$ 亿年，远大于宇宙年龄。汉诺塔递归程序的正确性可用数学归纳法证明：基础情况 $n=1$ 正确；假设 $n-1$ 正确，则 $n$ 由两次 $n-1$ 规模的正确移动和一次直接移动构成，因此正确。

构成递归必须满足两个条件：**递归规模必须严格变小**，否则可能无限递归；**必须有出口**，且出口要能兜住所有情况。例如每次减 $2$ 时不能只写 $n=1$，否则可能从 $2$ 跳到 $0$，需要写成 $n\le 1$ 或相应边界。

#### 递归树与剪枝

把递归调用过程画成一棵树，就得到**递归树**。递归树是对调用过程的可视化，按前序遍历方式理解：先深入最左分支，执行到底后回溯，再处理右分支。汉诺塔的递归树中，每个结点表示一次 `hanoi(n,A,B,C)` 调用，叶子对应具体的移动操作。

剪枝是通过减少无用递归调用提高效率的常见技巧。常见类型包括：

- **可行性剪枝**：当前状态的所有后续状态都不可能满足目标时，直接停止探索。例如求 `A,T,C,G` 的所有排列时，若某字符已经使用过，则不再继续放置。
- **最优性剪枝**：求解最优化问题时，若当前状态后续不可能优于已知最优解，则停止。例如求 `ATCG` 所有排列中字典序最小的排列，当已得到 `ATC...` 时，若当前前缀 `ATG` 已经更大，则无需继续。
- **记忆化**：当递归会重复调用相同状态时，用数组保存已计算结果。例如斐波那契数列中 $F(n)=F(n-1)+F(n-2)$，若不记忆化会大量重复计算；记忆化后每个状态只算一次。

N 皇后问题是剪枝的典型应用。在 $n\times n$ 棋盘上放置 $n$ 个皇后，使任意两个不在同一行、同一列、同一主对角线或次对角线。逐行放置皇后，枚举第 $j$ 列；若该列、主对角线、次对角线已有皇后，则立即剪枝，不再继续。常用四个数组：`col[n]` 标记列，`md[2n-1]` 标记主对角线，`sd[2n-1]` 标记次对角线，`q[n]` 记录每行皇后所在列。

#### 分治思想与 Strassen 矩阵乘法

分治的基本步骤是：**分解**，将问题划分为若干形式相同、规模更小的子问题；**解决**，子问题足够小时直接求解，否则递归求解；**合并**，将子问题解组合成原问题解。分治与递归关系密切：分治是更高层的算法思想，递归是实现手段。

分治复杂度分析中，若规模 $n$ 的问题分解为 $a$ 个规模 $n/b$ 的子问题，合并代价为 $O(n^k)$，则总复杂度可由主定理分析。归并排序是典型分治；实际实现中，当子问题规模小于阈值（如 $16$）时常改用插入排序，因为小规模下插入排序常数更小、更快。

Strassen 矩阵乘法展示了分治在矩阵乘法上的巧妙应用。朴素 $n\times n$ 矩阵乘法复杂度为 $O(n^3)$。将矩阵分成四个 $n/2\times n/2$ 子块后，朴素分块仍需 $8$ 次子矩阵乘法，复杂度仍为 $O(n^3)$。Strassen 构造了 $7$ 个中间矩阵 $M_1,\dots,M_7$，把乘法次数从 $8$ 次降为 $7$ 次，于是复杂度变为

$$
O(n^{\log_2 7})\approx O(n^{2.81})
$$

但 Strassen 增加了大量矩阵加减法和递归调用开销，小规模时反而比朴素乘法慢很多；只有规模足够大时优势才体现。Hopcroft 和 Kerr 已证明两个 $2\times 2$ 矩阵相乘至少需要 $7$ 次乘法，因此若继续改进需研究 $3\times 3$ 或更大分块。目前已知上界可达 $O(n^{2.373})$，是否存在 $O(n^2)$ 算法仍是未解问题。

### 递归与非递归

#### 递归的优缺点与栈帧

递归的优点是自然、简洁、直观，符合许多问题和数据结构的定义，易于维护。传统教材常说递归“代码执行效率低”，但老师强调这一结论**在今天基本不成立**。现代编译器对递归的优化已经很好，递归与非递归在效率上通常没有质的差别，有时手写非递归甚至不如编译器生成的代码快。

递归仍有一个现实风险：**栈空间溢出**。每次函数调用都会在栈区维护一个独立的**栈帧**，其中保存输入参数、局部变量、临时变量、返回值、返回地址以及上一个栈帧的地址等信息。递归深度过大时会消耗大量栈空间。实际工程中把递归改为非递归，更多是为了控制栈溢出，而不是单纯追求速度。

以阶乘 $F(n)=nF(n-1)$ 为例，调用 $F(3)$ 时会依次压入 $F(3),F(2),F(1),F(0)$ 的栈帧，每层保存当前的 $n$ 和返回地址，回溯时逐层恢复现场并计算返回值。

#### 递归转非递归的方法

递归转非递归大致分三类：

1. **通用方法：用栈显式模拟系统递归调用**。自己维护栈帧，保存参数、局部变量和返回地址，完全仿真递归过程。逻辑上与系统执行一一对应，只是把系统栈换成程序员自己管理的数据结构。
2. **尾递归与线性递归的公式化转换**。尾递归是递归调用位于函数最后一条语句的情况，可直接改为循环；线性递归有固定模板，可消除栈。尾递归消除的典型例子是阶乘改为循环。
3. **寻找与递归思路完全不同的迭代算法**。例如斐波那契数列可用递推，从 $F(0),F(1)$ 逐步推到 $F(n)$，时间复杂度 $O(n)$、空间 $O(1)$。这类方法依赖灵感，不具有通用性。

汉诺塔的非递归实现是重点难点。教科书标准方法是“递归树方法”：用栈保存 `(n,a,b,c)` 状态，模拟前序遍历递归树。另有“模拟执行”方法：把原递归代码的每一步拆成状态，利用 `goto` 和返回地址标签，手动保存现场、恢复现场。老师现场演示的代码可读性较差，但过程与递归严格等价，把看似五星难度的题拆成两三星难度。需要区分**过程等价**与**结果等价**：有些写法虽然结果正确，但额外压入了本不需要立即执行的调用，牺牲效率，不是过程等价。

尾递归消除示例：

```cpp
int factorial(int n) {
    int f = 1;
    for (int i = 2; i <= n; ++i) f *= i;
    return f;
}
```

线性递归的一般形式为：先执行 `S1(n)`，若 `Eval(n)` 成立则递归 `proc(n-1)` 后执行 `S2(n)`，否则执行 `S3(n)`。这类结构可公式化地转为非递归，避免栈操作，效率通常会提高。实际中若编译器不能自动识别优化，手动转换才有收益。

### 广义表

广义表是 $n\ge 0$ 个表元素组成的有限序列，记作

$$
LS=(a_0,a_1,\dots,a_{n-1})
$$

其中每个元素 $a_i$ 既可以是**原子**（普通数据元素），也可以是**子表**。$n$ 为表长度，$n=0$ 为空表。非空广义表的第一个元素称为**表头** `Head`，其余元素组成的表称为**表尾** `Tail`。注意表头是元素，表尾仍是广义表，二者类型不同。

例如：

- $A=()$：空表，长度 $0$，无表头表尾；
- $B=(6,2)$：线性表，长度 $2$，表头 $6$，表尾 $(2)$；
- $C=('a',(5,3,'x'))$：长度 $2$，表头 `'a'`，表尾 $((5,3,'x'))$，是子表；
- $D=(B,C,A)$：长度 $3$，表头 $B$，表尾 $(C,A)$；
- $F=(4,F)$：递归表，表尾仍为 $F$。

广义表的特性包括：有次序性、有长度、有深度、可递归、可共享。其结点通常用 `tag` 区分类型：`tag=0` 表示原子，存放数据；`tag=1` 表示子表，存放指向子表表头的指针。实现中常使用 `union` 让同一存储空间根据 `tag` 解释为整数、字符或指针。广义表可表示树形结构，在早期人工智能语言 Lisp、Prolog 中是核心数据结构。

### 排序初步

#### 排序的定义与稳定性

排序是将数据元素按关键字重新排列成有序序列。默认讨论升序。若关键字相同元素的相对次序在排序后保持不变，则称排序算法**稳定**；否则不稳定。稳定性的典型用途是多关键字排序：例如先按数学成绩排序，再按总分排序；由于第二次排序稳定，总分相同者仍保持数学成绩的先后次序。稳定排序有插入排序、冒泡排序、归并排序；不稳定排序有选择排序、快速排序、堆排序。

排序可按内存使用分为内部排序和外部排序。内部排序全部在内存完成；外部排序数据主要在外存，评价标准更看重外存读写次数，而不是 CPU 比较次数。按实现手段可分为基于比较的排序和基于分配的排序。基于比较的排序通过关键字比较交换位置；基于分配的排序通过分配和收集完成，如计数排序、基数排序、桶排序。计数排序在关键字范围很小时可达到线性时间，例如高考分数 $0\sim750$，只需开 $751$ 个桶，把考生按分数分配到桶中再依次收集即可。

#### 插入排序

插入排序的基本思想是：维护一个已排序前缀，每次取出当前元素，在已排序部分从后向前比较，找到合适位置插入。若当前元素小于前一个元素，则前一个元素后移，直到找到不大于当前元素的位置。插入排序可以保证稳定：遇到相等元素时不再向前插入，保留原有次序。

性能上，最佳情况为原序列有序，比较 $n-1$ 次、移动 $0$ 次，时间 $O(n)$；最坏情况为逆序，比较和移动均为 $O(n^2)$；平均时间 $O(n^2)$。空间复杂度 $O(1)$，只需一个临时变量。插入排序在元素个数较少时非常快，常作为高级排序的底层优化：当递归分治到规模小于阈值（如 $16$）时，改用插入排序。

#### 冒泡排序与选择排序

冒泡排序通过相邻元素比较和交换，把较大元素逐步“冒”到后面。未优化版本最坏和平均均为 $O(n^2)$，空间 $O(1)$，稳定。冒泡排序虽然直观，但实际中很难找到它比插入排序更优的典型场景。

选择排序每次从当前未排序部分选出最小元素，与第一个位置交换，然后对剩余部分重复。其比较次数固定为约 $n(n-1)/2$，最佳、最坏、平均时间均为 $O(n^2)$；空间 $O(1)$。选择排序的优点是交换次数很少，适合对移动次数敏感的场景；缺点是不稳定。例如序列中两个相等关键字可能因交换而改变相对次序。

### 一、第九周作业与机考讲评

#### 1. 少林寺：有序集合中找前驱与后继

题意是：师傅固定为 \(id=1\)，战斗分为 \(10^9\)；之后按加入顺序给出 \(n\) 个和尚。每个新和尚入寺时，要寻找寺中与他战斗分最接近的老和尚比武；若距离相同，选战斗分较低者。输出每场比武的“新和尚 id 老和尚 id”。战斗分互不相同，\(n\le 10^5\)，逐个比较是 \(O(n^2)\)。

核心观察：把所有老和尚按战斗分放在数轴上，距离新和尚 \(g\) 最近的人一定在 \(g\) 的前驱或后继中。前驱是小于 \(g\) 的老和尚中战斗分最大者；后继是大于 \(g\) 的老和尚中战斗分最小者。其他元素都在前驱左侧或后继右侧，距离只会更远。因此每次只需找 \(g\) 的前驱和后继，比较两个距离；若距离相等，按题意选战斗分低的前驱。

实现上用 `std::map<战斗分, id>` 或 `std::set` 维护已入寺和尚。`lower_bound(g)` 返回第一个战斗分大于 \(g\) 的位置，即后继；它的前一个迭代器就是前驱。若 `hi == monks.begin()`，说明没有比 \(g\) 小的老和尚，只能选后继。否则令 `lo = prev(hi)`，比较：

\[
g-lo.first \quad \text{与} \quad hi.first-g
\]

若前者小于等于后者，选前驱，因为相等时选分低者；否则选后继。最后把当前和尚插入 `monks[g]=id`。时间复杂度 \(O(n\log n)\)。师傅战斗分 \(10^9\) 大于所有 \(g\)，因此后继实际上不会越界，但代码保留 `hi==end()` 判断更稳健。

#### 2. 石子合并：哈夫曼贪心

题意：有 \(n\) 堆石子，每次任选两堆合并，代价为两堆数量之和，求合并成一堆的最小总代价。注意这里“任意两堆”可以合并；若只能合并相邻两堆，则是区间 DP，贪心不成立。本题 \(n\le 10^5\)，\(a_i\le 10^6\)，样例 \(5,8,8\) 的最优过程为：先合并 \(5+8=13\)，花费 \(13\)；再合并 \(13+8=21\)，总花费 \(34\)。若先合并两个 \(8\)，花费 \(16+21=37\)，更差。

把任意合并过程画成一棵二叉树：叶子是原来的石子堆，内部结点是一次合并，结点值是该次合并的代价。某堆石子在它到根的路径上每经过一次合并就被计一次，因此总代价为：

\[
\sum_i a_i \times \text{depth}_i
\]

其中深度从叶子到根计算。于是问题变成：给定叶子权值，构造一棵二叉树，使加权深度和最小。这就是哈夫曼树思想：权值大的堆应放浅，权值小的堆放深。

贪心策略：每次合并当前最小的两堆。证明用交换论证。设 \(x\le y\) 是当前最小的两堆。取一棵最优树，最深一层必有两片兄弟叶子 \(u,v\)。把 \(x\) 与 \(u\) 交换，把 \(y\) 与 \(v\) 交换。由于 \(x\le u\)，交换后 \(x\) 变深、\(u\) 变浅，代价变化不为正；同理交换 \(y\) 也不增代价。因此存在一棵最优树让 \(x,y\) 在最深层做兄弟。合并 \(x,y\) 后剩 \(n-1\) 堆，总代价减少 \(x+y\)，对堆数归纳即可。

实现用优先队列小根堆：

```cpp
priority_queue<long long, vector<long long>, greater<long long>> heap(a.begin(), a.end());
long long cost = 0;
while (heap.size() > 1) {
    long long x = heap.top(); heap.pop();
    long long y = heap.top(); heap.pop();
    cost += x + y;
    heap.push(x + y);
}
```

`priority_queue` 默认是大根堆，传入 `greater<long long>` 才是小根堆。用整个数组初始化堆是 \(O(n)\) 的。总复杂度 \(O(n\log n)\)。总代价可能达到约 \(2\times 10^{15}\)，必须用 `long long`。

#### 3. 前缀 TopK：只插入不删除的小根堆

题意：对长度为 \(k,k+1,\dots,n\) 的每个前缀，输出其中最大的 \(k\) 个数之和。共有 \(n-k+1\) 个输出。\(n\le 10^5\)，元素绝对值可达 \(10^9\)，可以有负数和重复值。样例 \(2,6,3,4,5,1\)，\(k=3\)，输出为 \(11,13,15,15\)。

如果每个前缀都排序，复杂度 \(O(n^2\log n)\)。观察本题只有插入、没有删除，因此可以用一个小根堆维护当前前缀中最大的 \(k\) 个数。堆顶是这 \(k\) 个数中最小的那个，相当于“门槛”。

处理新数 \(x\) 时：若堆大小不足 \(k\)，直接放入；若堆已满且 \(x\le\) 堆顶，则 \(x\) 进不了前 \(k\) 大，直接丢弃；若 \(x>\) 堆顶，则弹出堆顶，插入 \(x\)。同时维护堆内元素和 `sum`。替换时：

\[
sum \leftarrow sum + x - \text{oldTop}
\]

不必每次重新求和。时间复杂度 \(O(n\log k)\)。答案可能达到 \(k\times 10^9\approx 10^{14}\)，要用 `long long`。

#### 4. 新-合并果子：除以 2 的合并与单调队列优化

题意：每次合并两堆 \(x,y\)，消耗体力为 \((x+y)/2\)，求最小总体力，保留一位小数。数组已经按不降序排好；有 \(T\le 20\) 组，第一组完整给出数组，之后每组由上一组修改若干个数得到。\(n\le 5\times 10^5\)，总修改数 \(\sum m\le 10^5\)。OJ 禁用 O2，建议线性做法、少用 STL。

关键归约：本题每次体力都是石子合并问题代价的一半，因此任何方案的总体力等于总代价除以 2。所以最优方案完全相同，仍然是每次合并最小的两堆；本题最优体力就是第 2 题最小代价除以 2。

但不能直接建堆：\(T=20,n=5\times 10^5\)，堆做法在禁用 O2 时风险很大。利用数组已经有序，可以用两个单调队列代替堆：

- 队列 A：原数组，已经按不降序排列。
- 队列 B：按产生顺序存放合并出的新堆。

每次从 A 的队首、B 的队首中取两个最小值。若两个都来自 A，就取 A 的前两个；若两个都来自 B，就取 B 的前两个；若一个来自 A、一个来自 B，就比较两个队首。合并得到的新堆压入 B 的尾部。

为什么 B 不降？设第 \(t\) 次取出当前最小的两堆 \(x\le y\)，新堆 \(s=x+y\)。第 \(t\) 次之后剩下的旧堆都不小于 \(y\)，而新堆 \(s=x+y\ge y\)，所以此后所有堆都不小于 \(y\)。因此 B 中元素按产生顺序不降。于是全局最小值只可能是 A 队首或 B 队首，每次比较两个队首即可。

输出一位小数时不要经过 `double`。总代价可达约 \(9.5\times 10^{15}\)，超过 double 能精确表示整数的范围 \(2^{53}\)。正确做法是用整数保存“两倍体力” `cost2`，最后先输出 `cost2/2`，再根据 `cost2` 的奇偶输出 `.5` 或 `.0`。样例 \(1,1,1,1,1\) 的体力为 \(6.0\)；\(1,1,1,2,4\) 的体力为 \(9.5\)。读入可用 `getchar` 手写快速读入，每组 \(O(n)\)，总复杂度约 \(O(Tn+\sum m)\)。

#### 5. 你美还是我美：绝对值拆开与前缀和

题意：给定两个数组 \(a,b\)，求

\[
\sum_{i=1}^{n}\sum_{j=1}^{m}|a_i-b_j|
\]

其中 \(n,m\le 2\times 10^5\)，值不超过 \(10^8\)。直接枚举有 \(n\cdot m=4\times 10^{10}\) 对，必然超时。样例 \(a=1,2,3\)，\(b=1,10\)，答案为 \(27\)。

固定一个 \(x=a_i\)，把 \(b\) 排序。设排序后 \(b\) 中有 \(c\) 个元素不超过 \(x\)。对前 \(c\) 个 \(b_j\le x\)，贡献为 \(x-b_j\)；对后 \(m-c\) 个 \(b_j>x\)，贡献为 \(b_j-x\)。因此：

\[
\text{贡献}
=
\left(xc-\text{pre}[c]\right)
+
\left(\text{pre}[m]-\text{pre}[c]-x(m-c)\right)
\]

其中 `pre[c]` 是排序后 \(b\) 的前 \(c\) 个元素前缀和。`c` 用 `upper_bound(b.begin(), b.end(), x)-b.begin()` 求出，返回第一个大于 \(x\) 的位置，正好是 \(\le x\) 的个数。等于 \(x\) 的元素归入哪一侧都可以，因为贡献为 0。

复杂度为排序 \(O(m\log m)\)，每个 \(a_i\) 二分并 \(O(1)\) 求贡献，共 \(O(m\log m+n\log m)\)，空间 \(O(m)\)。答案上界约为 \(4\times 10^{10}\times 10^8=4\times 10^{18}\)，小于 `long long` 上限约 \(9.22\times 10^{18}\)，但中间乘法要用 `long long`。这道题也体现了“把对所有 \(j\) 的求和拆成前缀/后缀两段”的常见技巧。

#### 6. 讲评中的工程与比赛讨论

新-合并果子出现较多“卡常”问题。课堂现场查看了提交与榜单，有同学因函数调用、数组大小、STL 使用、评测时间设置等被卡。老师提到：把 `solve()` 等函数内容展开到主函数虽然难看，但可能减少函数调用开销；开两个数组、三个数组等细节也可能影响。助教后续会对相关提交单独更正、重测。

### 二、高级排序总览

简单排序与高级排序不是严格分类，只是约定：简单排序通常指平均复杂度 \(O(n^2)\) 的排序；高级排序指平均复杂度 \(O(n\log n)\) 的排序。本次讲三个高级排序：归并排序、堆排序、快速排序。

从手写代码角度，归并排序通常最好写，思路清晰；快速排序的 `partition` 稍麻烦；三者都不算难写。归并和快排都基于分治，但归并是二等分，快排按主元分成两块，不保证等分。堆排序则依赖完全二叉树和堆结构。

### 三、归并排序

#### 1. 基本思想与二路归并

归并排序基于分治：将两个或两个以上的有序序列合并成一个新的有序序列。二路归并是每次在两个已排序序列中分别取当前最小项，比较后把较小者放入新序列，直到两序列全部合并。多路归并是合并多于两个序列。

内存中通常用二路归并，因为三路归并每次可能要比较两次，而二路只需比较一次；除非路数接近 \(2\) 的幂，否则多路并不一定更优。外存排序中则常用多路归并，因为外存排序更关心减少读写外存的次数，而不是单纯比较次数。

归并次序有自顶向下和自底向上两种，效率等价。

#### 2. 自顶向下归并过程

以数组 \((25,34,45,32,78,12,34',64)\) 为例。先不断二分，直到每个子数组长度为 1；长度 1 天然有序。然后两两合并：\((25,34)\)、\((45,32)\) 合并为 \((25,34)\) 与 \((32,45)\)，再合并为 \((25,32,34,45)\)；右侧类似。最后两个长度 4 的有序段合并为长度 8 的有序数组。

合并时，每次比较两个有序段的首元素，取较小者放入结果。若相等，优先取左边段中的元素，因此归并排序可以保证稳定。归并排序的递归结构为：

```cpp
void MergeSort(Item a[], int l, int r) {
    if (r <= l) return;
    int m = (l + r) / 2;
    MergeSort(a, l, m);
    MergeSort(a, m + 1, r);
    merge(a, l, m, r);
}
```

核心是 `merge`。最直观写法是开一个等大的辅助数组，将合并结果写入辅助数组，再拷贝回原数组；或者先把原数组拷贝到辅助数组，再合并回原数组。无论哪种，每层归并都需要一次拷贝。辅助数组是归并排序空间开销的主要来源。

#### 3. 自底向上归并

自底向上不递归划分，而是直接按宽度 \(1,2,4,8,\dots\) 合并相邻有序段：先两个长度 1 合并为长度 2，再两个长度 2 合并为长度 4，依此类推；最后不足整段的也合并。结果与自顶向下相同，效率也等价，包括辅助空间。

#### 4. 复杂度、稳定性与适用场景

归并排序每轮归并最多处理 \(n\) 个元素，共约 \(\log_2 n\) 轮，因此时间复杂度 \(O(n\log n)\)。比较次数也是 \(O(n\log n)\)，后续算法分析课会进一步分析常数项。空间复杂度 \(O(n)\)，需要辅助数组。归并排序稳定。

归并排序适合外部排序，也适合链表等不便随机访问的结构；但它需要额外空间，且数组拷贝开销较大。

#### 5. 归并排序的优化

常见优化有四类：

1. **小规模子数组使用插入排序**。当区间长度小于等于阈值（如 16）时，不再递归划分，直接调用插入排序。小数组上插入排序常数小，通常更快。
2. **检测待归并数组是否已经有序**。合并前比较左段最大值与右段最小值，若 `a[m] <= a[m+1]`，说明两段整体已经有序，直接跳过本次 `merge`。数据基本有序时收益明显；随机数据下多一次判断，收益不一定大。
3. **去除原数组到辅助数组的拷贝**。通过增加辅助数组参数，在递归层交替交换原数组与辅助数组的角色。为避免判断递归层数奇偶，可以先把原数组复制到辅助数组，最后一层再合并回原数组；这样程序简单且一定正确。该优化对性能贡献最大。
4. **并行优化**。归并排序天然适合分治并行，左右子数组可并行排序，最后合并；课程不作要求。

C++ 的 `std::stable_sort` 核心算法就是归并排序，并使用了上述优化，短序列阈值通常为 16。若申请不到足够额外空间，`stable_sort` 还会使用原地归并 `in-place merge`：堆空间可降到 \(O(1)\)，但归并本身从 \(O(n)\) 变为 \(O(n\log n)\)，总排序时间变为 \(O(n\log^2 n)\)，递归栈空间为 \(O(\log n)\)。

#### 6. 循环右移与原地归并

原地归并的朴素做法是：合并两段时，若右段元素应插入左段前面，就把左段整体循环右移一位，再插入。单次插入可能移动 \(O(n)\)，最坏总复杂度 \(O(n^2)\)，不可接受。

一个经典技巧是“批量循环右移”：若要把长度为 \(k\) 的一块整体移到前面，不必一位一位移，可以用三次翻转实现。例如把 \(5,7,4,2,3,4\) 中右侧的 \(2,3,4\) 移到前面，可以先整体翻转，再分别翻转两段，从而在 \(O(n)\) 时间内完成一次批量旋转。该技巧能把一次块移动控制在 \(O(\text{块长})\)。但它仍可能退化为 \(O(n^2)\)，例如左段全是奇数、右段全是偶数时，难以找到大批量整体旋转的机会。

真正的原地归并用二分思想。合并 \([l,m]\) 与 \([m+1,r]\) 时，先把左段二分，取左段中间元素；在右段中二分找到第一个大于等于该元素的位置，将中间一段通过线性旋转交换。这样一次旋转后，问题被分成两个规模更小的归并子问题，递归处理。每次旋转是线性的，递归深度 \(O(\log n)\)，因此单次归并 \(O(n\log n)\)，总排序 \(O(n\log^2 n)\)，堆空间 \(O(1)\)，栈空间 \(O(\log n)\)。这个例子很巧妙，体现了“二分不一定只能二等分，也可以按大小关系分”。

### 四、堆与堆排序

#### 1. 完全二叉树与堆的定义

完全二叉树：除最后一层外，其余层都是满的；最后一层从左到右连续排列，不能中间空缺。因此完全二叉树可以不用指针，而用数组按层序存储。若下标从 0 开始，则：

\[
\text{parent}(i)=\left\lfloor\frac{i-1}{2}\right\rfloor,\quad
\text{left}(i)=2i+1,\quad
\text{right}(i)=2i+2
\]

若下标从 1 开始，则 `parent(i)=i/2`，`left(i)=2i`，`right(i)=2i+1`。这些公式不必死记，现场推导即可。

堆是完全二叉树的特例，并附加堆序性质：最大堆中每个结点值大于等于其左右孩子；最小堆中每个结点值小于等于其左右孩子。因此最大堆堆顶是全局最大值，最小堆堆顶是全局最小值。优先队列通常用堆实现，核心操作是取堆顶、插入、删除堆顶。

#### 2. `shift_down` 向下调整

`shift_down(i)` 用于把位置 \(i\) 的元素向下调整到合适位置。每次比较 \(i\) 的左右孩子，选较大的孩子；若该孩子大于当前元素，则把该孩子上移，继续向下；直到没有孩子或当前元素已经不小于孩子为止。这个过程类似“在树上做插入排序”，不是简单冒泡交换，而是先把待调整元素暂存，最后填到最终位置。

`shift_down` 的时间复杂度为 \(O(\log n)\)，与树高有关。

#### 3. 建堆：从最后一个非叶结点向前调整

把一个无序数组建成堆：先把它看成完全二叉树，然后从最后一个非叶结点开始，向前对每个结点执行 `shift_down`。最后一个非叶结点约为 \(n/2-1\)（0 开始下标）。代码就是一个倒序循环加 `shift_down(i)`。

建堆复杂度很容易误判为 \(O(n\log n)\)：共有约 \(n/2\) 个结点，每次 \(O(\log n)\)，看似 \(O(n\log n)\)。但这是松上界。精确分析：高度为 \(h\) 的结点最多约 \(n/2^{h+1}\) 个，每个向下调整代价 \(O(h)\)，于是：

\[
\sum_{h=0}^{\lfloor\log n\rfloor} \frac{n}{2^{h+1}}O(h)=O(n)
\]

因此建堆是线性时间 \(O(n)\)。这是堆的重要理论结论，也是堆能高效支持 TopK 的基础。教材中若有“建堆 \(O(n\log n)\)”的写法，应视为不精确或错误。

#### 4. `shift_up`、插入与删除

`shift_up(i)` 用于向上调整：把位置 \(i\) 的元素与其父结点比较，若大于父结点（最大堆）则上移，继续向上，直到满足堆序。插入时把新元素放到数组末尾，然后 `shift_up`。删除堆顶时，取出堆顶，把末尾元素填到堆顶，堆大小减一，再 `shift_down(0)`。两者均为 \(O(\log n)\)。

#### 5. 堆排序

堆排序升序排序时，建最大堆；然后重复：把堆顶（当前最大值）与堆末尾交换，堆大小减一，对堆顶执行 `shift_down`。这样最大值依次放到数组末尾，最终得到升序。代码非常短，核心就是建堆循环加排序循环。

堆排序时间复杂度 \(O(n\log n)\)，空间复杂度 \(O(1)\)，是堆排序相对归并排序的优点。但堆排序不稳定：堆顶与末尾元素交换可能跳过相等元素，破坏相对顺序。

TopK 也可以用堆：求最大 \(k\) 个数可维护大小为 \(k\) 的小根堆；或建大根堆取 \(k\) 次堆顶。每次取堆顶 \(O(1)\)，调整 \(O(\log n)\)。

#### 6. 修改堆中任意元素

一般教材只讲插入、删除，但堆中任意位置元素被修改也应支持。做法很简单：修改位置 \(i\) 后，直接调用 `shift_up(i)` 和 `shift_down(i)` 各一次，不需要判断是变大还是变小。因为其中一个方向会自然判断“不需要调整”，另一个方向若需要则会调整。这样代码简单且正确。

### 五、快速排序

#### 1. 基本思想与主元

快速排序本质也是分治，但不是二等分。它选择一个“主元”（pivot，也称界点、支点、中心值），通过划分把数组分成两部分：左边元素不大于主元，右边元素不小于主元；主元放到最终位置。然后递归排序左右两部分。

主元可选首元素、尾元素、随机元素或三数取中。简单实现常选最后一个元素。划分是快排的核心，划分完成后主元位置 \(q\) 已确定，左边 \([l,q-1]\) 和右边 \([q+1,r]\) 分别递归。

#### 2. 划分过程

以取最后一个元素为主元为例：先把主元暂存到临时变量 \(T\)，数组末尾位置视为空位。设置 `low` 和 `high` 指针向中间移动：`high` 从右向左找第一个小于主元的元素，`low` 从左向右找第一个大于主元的元素，交换二者；重复直到 `low` 与 `high` 相遇。最后把 \(T\) 填入相遇位置。这样主元左边都不大于它，右边都不小于它。

`partition` 是线性时间 \(O(n)\)。快排递归框架：

```cpp
void QuickSort(int a[], int l, int r) {
    if (r <= l) return;
    int q = partition(a, l, r);
    QuickSort(a, l, q - 1);
    QuickSort(a, q + 1, r);
}
```

快排代码不长，但划分写法多样。早期教材有些写法效率较差，现在常见写法差异不大。

#### 3. 最坏情况与平均性能

快排与归并、堆排序的重要区别是：它有明显的坏情况。若每次取首元素或尾元素为主元，而数组已经完全有序，则每次划分一边为 0 个、一边为 \(n-1\) 个，递归深度 \(n\)，每层 \(O(n)\)，总复杂度退化为：

\[
T(n)=T(n-1)+O(n)=O(n^2)
\]

空间上，递归栈最坏也为 \(O(n)\)。平均情况下，快排复杂度为 \(O(n\log n)\)，递归栈平均 \(O(\log n)\)。平均比较次数约为 \(1.39n\log_2 n\)，在归并、堆、快排三者中常数最小。因此随机数据下快排通常最快，这也是它名字的由来。但注意：只是在“基于比较的这三个排序”中平均最快；后续会看到很多特定场景下快排并不是最快。

#### 4. 快速排序的优化

常见优化包括：

1. **小规模子数组使用插入排序**。当区间长度小于阈值（如 16）时，直接插入排序，不再递归。与归并优化类似。
2. **三数取中选主元**。取首、中、尾三个数的中间值作为主元，避免主元恰好是最小或最大，减少已排序数据退化的概率。但若策略固定，仍可构造数据使其变坏；它是减少极端情况，不是完全避免。
3. **三路划分处理重复值**。将数组划分为小于主元、等于主元、大于主元三段，等于主元的一批元素一次性放到中间，不再递归。重复值很多时收益显著。
4. **短序列优先与递归栈控制**。快排有递归空间开销。若把长段先递归、短段后递归，仅仅交换递归顺序并不能降低递归栈深度；需要把长段改为尾递归消除，或用显式栈实现非递归，并先处理短段、把长段压栈，才能把辅助栈深度控制在 \(O(\log n)\)。这个点不太直观，需要课后用草稿验证。注意：非递归加短序列优先会带来时间上的额外开销，实验中甚至可能明显变慢，这是为控制空间付出的代价。

`std::sort` 的主干是 `introsort`：以快排为主，当检测到快排有退化迹象时切换为堆排序接管，保证最坏 \(O(n\log n)\)；同时结合插入排序处理小数组。因此现代 `std::sort` 不会像朴素快排那样退化到 \(O(n^2)\)。

### 六、三种高级排序对比

| 排序 | 平均时间 | 最坏时间 | 空间 | 稳定性 | 特点 |
|---|---:|---:|---:|---|---|
| 归并排序 | \(O(n\log n)\) | \(O(n\log n)\) | \(O(n)\) | 稳定 | 好写，适合外部排序、链表；需辅助数组 |
| 堆排序 | \(O(n\log n)\) | \(O(n\log n)\) | \(O(1)\) | 不稳定 | 空间优，适合 TopK、优先队列；常数较大 |
| 快速排序 | \(O(n\log n)\) | \(O(n^2)\) | 平均 \(O(\log n)\)，最坏 \(O(n)\) | 不稳定 | 平均最快，常数小；需优化避免退化 |

归并排序的稳定性来自合并时相等取左；堆排序不稳定来自堆顶与末尾的大范围交换；快排不稳定来自划分交换。实际库函数通常采用混合排序：小数组插入排序，快排为主，退化时堆排接管。

### 七、课后任务

- 读懂并手写 `shift_down`、`shift_up`，理解它们本质上是在完全二叉树上做插入排序式的调整。
- 自己推导建堆复杂度为什么是 \(O(n)\)，不要停留在“循环 \(n/2\) 次、每次 \(\log n\)”的松上界。
- 验证快速排序中“仅交换递归顺序不能降低递归栈深度”，理解为什么非递归/显式栈加短序列优先才能控制栈深。
- 阅读归并排序 `merge` 的多种写法，重点掌握稳定合并与辅助数组拷贝的去除方法。
- 预习 `introsort`：快排、堆排、插入排序如何组合，以及为什么它能保证最坏 \(O(n\log n)\)。
